# Agent Note: 合并接入维护体系

Status: implemented

## 问题

TeXlate 需要文档、注释与长期决策维护的方法和可执行检查，同时已有产品 CI、文档分区、ADR 和格式化链。完整覆盖上游配置会丢失产品验证职责。

## 决策

按固定上游提交接入维护技能、参考、模板与检查器，复用现有工具链。维护检查加入提交快照、推送钩子和 CI。上游自身的过程记录不复制；现有 ADR 不迁移，Agent Notes 只补充没有归属的长期理由。

目标是验证维护工具能在本仓正常运行，并能拒绝断链、非法 Notes、封存改写与失败依赖。成功证据由 `scripts/tests/` 的隔离仓库正反例及本仓真实检查共同提供；扫描到本机现场、遗漏暂存差异或维护检查替代产品检查都不满足接入要求。检查调度配置、扫描边界和安装入口允许按实测调整。

## 考虑过的替代方案

直接覆盖根工具链会丢失 TeXlate 自有检查。只复制 SKILL.md 会缺失引用资源和可执行保护。另建全套上游独立环境会制造依赖与版本的第二个事实源，因此采用合并接入。

## 后果

维护工具按上游固定提交留存来源与许可；后续升级需要审查本地适配。维护检查不证明产品行为或示例命令正确，相关产品验证仍按改动范围运行。可信封存保护在目标分支包含检查器后生效；分支合并规则的启用属于托管平台配置。
