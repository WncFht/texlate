# Agent Note: Python 核心与外部文档引擎

Status: implemented

## 问题

项目需要 LaTeX、PDF、模型调用与文档处理生态，同时控制安装成本、前端交互复杂度和第三方许可边界。

## 决策

Python 3.12+ 负责产品核心、服务与 CLI，uv 管理环境；TypeScript 负责 Web 与 Zotero 客户端。tectonic 提供可管理的便携引擎，系统 XeLaTeX 覆盖补充能力。

PDF 翻译使用 BabelDOC CLI sidecar，主产品不 import 该引擎；EPUB 使用 zip/XML 自行插译，DOCX 使用 python-docx。电子书保留原段落并插入译文，DRM、fixed-layout 等不支持输入须明确拒绝。进程边界是工程与依赖选择，不替代第三方许可核验；发布依据 LICENSE、NOTICE 与实际 bundled 资产。

## 考虑过的替代方案

全 TypeScript 或 Go/Rust 核心会放弃既有 Python 文档生态，尚无性能证据抵偿迁移成本。服务端模板不足以承担高频双 pane 交互。BabelDOC 进程内调用增加依赖与许可耦合；EbookLib 未作为 EPUB 生成依赖。OCR 到 Markdown 重排不满足保留论文版面的主要路径，但可用于独立场景评估。

## 后果

sidecar 有独立安装与进程生命周期，失败必须隔离并报告。电子书插译不承诺全部 Office/EPUB 格式无损；样式、容器和断点协议需专项测试。用户操作见 `docs/guide/export-share.md`，PDF/电子书路径的实现以所属包和测试核验。
