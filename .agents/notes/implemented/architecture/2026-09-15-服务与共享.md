# Agent Note: 单机服务、渠道和共享信任

Status: implemented

## 问题

任务需支持恢复、实时进度、租户隔离与译文复用；本机安装也需要低部署成本。共享包可携带损坏或被篡改的源码与元数据。

## 决策

采用 FastAPI、SQLite WAL 与进程内调度。任务事件独立持久化，客户端可重放并收养去重任务。retry 可以复用同一 task id；事件消费必须支持终态回到执行态。

渠道文件统一端点、凭据、模型与路由，旧配置一次性迁移。环境变量引用只存名称，公开输出脱敏；请求级凭据不写入任务事件。local 与 server 明确分离认证和配置写入面。

缓存与共享键包含源版本、模型、语言、prompt、术语和管线等语义。共享包先校验格式、键和逐件摘要，再在消费端重跑校验与编译；摘要自洽不能证明译文可信。无模型调用复用仍可能因编译环境不同失败。

## 考虑过的替代方案

Redis/Huey 增加初期部署面，尚无需求证明必须替换单机调度。内存事件无法重放；retry 另建任务会割裂客户端状态。公共译文 registry 涉及许可、存储与信任治理，保留交换包而不承诺公共托管。

## 后果

SQLite 单机模型不提供跨副本共享调度保证。文件摘要和任务租户校验缺一不可，用户收藏使用数据库快照以抵抗目录瘦身。API 与持久配置契约见 `docs/spec/server.md`。
