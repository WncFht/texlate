# Agent Note: 依赖薄封装与显式位置证据

Status: implemented

## 问题

双语 PDF 经重排后不能按绝对页码同步；引用跳转还需支持返回、触屏和键盘。暗色页面既要保持图像与彩色信息，也要避免维护 pdf.js fork。

## 决策

SolidJS 与 pdfslick 保持薄封装，named destination 和 seq 标记提供可验证的位置证据，缺少证据时保留近似或无锚。源 PDF 与自编译产物的锚体系不视为可互换。

内链统一包装跳转入口，以每 pane 内存栈记录真实导航；配对镜像各自恢复原位。卡片本地条目优先，服务端元数据代理只是增强，不能阻断阅读。收藏保存数据库快照，源码复制只返回有来源证据的切片。

全站使用单一色板轴；PDF 改色按图元和图像分类，以 document 实例补丁接入，不改全局 canvas 原型。none 模式作为原纸逃生口。当前交互与对齐契约分别见 `docs/spec/reader.md` 和 `docs/spec/reader-alignment.md`。

## 考虑过的替代方案

pdf.js PDFHistory 会写浏览器 hash，干扰 SPA 路由；只拦 click 事件不能覆盖所有内链入口。CSS 反色会伤照片，双色 pageColors 会丢彩色信息；fork pdf.js 会增加升级成本。每次 hover 直连公共元数据池会放大限流。文件 sidecar 会被任务瘦身清除，不适合保存用户收藏。

## 后果

位置匹配、导航顺序和主题重渲需分别验证。表格、数学字形、页眉重放与无标记历史任务仍有边界。未实施的选区翻译不作为现有接口；只有新的需求与资源方案成立才重新提出。实验见 `docs/research/2026-10-16-对齐与阅读器实验.md`。
