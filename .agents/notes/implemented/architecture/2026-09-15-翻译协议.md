# Agent Note: 无状态分批翻译与保真校验

Status: implemented

## 问题

模型会漏项、改锚或破坏控制序列；全篇 agent 反复携带上下文有较高调用与输入成本。协议正确、译文可读和编译成功需要不同证据。

## 决策

按内容 kind 分批，无状态请求使用稳定公共条款、术语与成员占位符名单。源与译文做相对校验，失败按阶梯重试；保留最终回原文或降级状态，不把回退文本算作成功译文。断点命中同时核对源内容，不能只认旧位置 id。

客户端以 httpx 实现 OpenAI、Anthropic 与 Responses 方言。渠道与认证在服务端统一管理，协议常量和实际 prompt 保留在代码中。模型准入看硬契约与可用性，历史免费档和促销不形成永久产品保证。

## 考虑过的替代方案

整篇交给通用 agent 会重放工作记忆，调用次数更难约束。把文档全部占位符恒等表放进每次 system 会放大缓存 miss 成本，已由成员名单替代；只靠 prompt 不做回包校验无法阻止静默丢项。统一第三方模型中间层曾引入额外参数透传风险，保留直接协议实现。

## 后果

批次与缓存需要显式版本纪律。成员重试仍可能放大调用次数，上游限流和认证失败需有界传播。成本实验保留负结果和小论文反例，见 `docs/research/evidence/token-economy/README.md`；当前契约见 `docs/spec/translate.md`。
