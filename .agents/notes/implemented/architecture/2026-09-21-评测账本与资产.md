# Agent Note: 追加账与按再生成本分区

Status: implemented

## 问题

实验重复执行会重复消费模型额度，目录存在又不能证明付费产物有效。历史恢复中失败的 splice 曾被作为有效字节复封，使后续修复被去重跳过。

## 决策

ledger 追加事件为账务权威，index 只是可重建投影。runs 保存执行材料，vault 保存付费字节，lake 保存免费载荷；不按文件后缀猜测再生成本。去重与付费授权结合生产者、variant、有效字节和声明能力，缺证据时拒绝付费执行。

编译失败、翻译失败、供应失败与版面失败分开记账。回放使用副本，历史补跑与当前重评各自注明版本。质检分档决定是否阻断和保留诊断，不能用“产出 PDF”决定删除免费工作区，更不能顺带清除 vault。

## 考虑过的替代方案

仅凭目录、status 或 kind 判成功会将陈旧半成品永久当命中。把整个实验库放进 checkout 会混合源码与大载荷。把所有文件当可再生缓存会丢失不可再生的付费译文。只备份索引无法恢复事件账与付费真身。

## 后果

快照恢复后需要对账，元数据备份不能代替 vault 载荷备份。清理必须服从所有权、保留等级和唯一恢复源约束。当前规范见 `docs/spec/bench-trizone.md`，关键事故见 `docs/research/2026-10-16-评测存储经验.md`。
