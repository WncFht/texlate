# Agent Note: 前后端与执行架构重构

Status: proposed

## 问题

TeXlate 是多客户端系统。`web/` 提供 SolidJS 阅读器与任务 UI；Zotero 插件和 `texlate run --server` 也消费服务 API。`server/` 通过 FastAPI 提供 HTTP/SSE、租户与凭据策略、SQLite 持久化、任务队列和产物服务。翻译与编译主体位于 `latex/`、`xlat/`、`compile/` 和共享管线策略 `pipecore/`。CLI 本地执行经 `e2e.py`，服务执行经 `server/worker/`，两路共享部分策略但保留不同的顶层阶段编排。

当前数据库同时保存任务、段落、事件、缓存、渠道和阅读收藏。任务重试保留 `task_id` 并追加事件；前端因此维护事件水位、重试状态清理、每任务 SSE 槽和轮询降级，还独立轮询段落正文。阅读器装载 manifest、reader 响应与 `dual.json`，自行判断任务类型和产物能力。读面和写面交织的证据见 `docs/spec/server.md`、`docs/spec/reader.md`、`web/src/stores/tasks.ts`、`web/src/stores/taskTransport.ts`、`src/texlate/server/worker/core.py` 与 `src/texlate/pipecore/`。

截至 2026-10-18 的工作树审计纳入未提交文件：Python 393 个源文件、112469 行；Web 209 个源文件、51149 行，其中 130 个不在 `test/` 目录；Zotero 19 个源文件、3235 行。临时应用生成的 OpenAPI 有 36 个操作、0 个请求体声明、0 个带业务字段的组件 schema。精确观测由 `docs/research/evidence/frontend-backend-architecture/audit.py` 在源码树哈希下重算；行数不等于复杂度或重写收益，运行时边界还需测试和部署测量。

## 提案

采用四层逻辑架构：输入/阅读器适配器、应用服务、产品 pipeline、基础设施适配器。第一层包括 Web、CLI、Zotero、REST 和 SSE；第二层统一任务创建、取消、重试、授权决议、结果查询与任务协调；第三层负责取源、解析、翻译、重建、编译、修复及结果判定；第四层提供数据库、任务派发、对象存储、模型客户端和编译子进程。pipeline 不依赖 HTTP、FastAPI、SQLite 或前端类型，但接受执行上下文、取消检查和类型化事件 sink。短期在现有 Python 项目内引入应用服务与端口，不为模块图而拆成独立微服务。

保留 Python 处理核心、FastAPI、Typer、SolidJS 与 PDF.js/pdfslick。Python LaTeX 解析、模型调用、PDF、Office 与压缩包生态构成现有能力，完整换语言没有已测量的性能或可靠性理由。保留 SolidJS 信号模型和 PDF 阅读器适配层；重写 Web 时先处理服务状态重复、API 类型、任务流和页面容器，不重写双栏同步、选区、引用、导航栈及 PDF.js 集成。Zotero 作为独立客户端继续消费版本化服务 API。

以 Pydantic 请求/响应模型补全 FastAPI OpenAPI，生成 Web 和 Zotero 共用的 TypeScript 数据类型。OpenAPI 描述 REST 资源、上传、错误和 SSE 的事件 envelope/游标语义；复杂阅读器事件另有显式版本化 schema。不得直接序列化 Python 内部 dataclass 或数据库行。阅读 UI 不参与产品 API schema 的定义。

将任务身份、执行轮次、产物版本拆开。`task` 表示用户意图与输入；`attempt` 表示一次可重试执行，`attempt_id` 单调递增且拥有状态、错误和运行统计；`artifact` 表示 attempt 产出的不可变版本。源内容和用户配置在创建时形成稳定快照。重试新建 attempt，产物和事件总能定位至具体轮次，阅读器默认引用最新可读 artifact revision，历史轮次保留明确引用。先用兼容投影映射当前单表 `tasks.status`、`task_events` 与 `files`，迁移指南另列发布步骤。

定义资源导向 API：`POST /api/v1/tasks` 接受 discriminator 联合输入（arXiv、任务上传句柄、共享包）；`GET /tasks` 返回 `TaskSummary` 页；`GET /tasks/{id}` 返回 `TaskDetail`；`POST /tasks/{id}/attempts` 创建执行轮次；`POST /attempts/{id}:cancel` 请求取消；`GET /attempts/{id}` 读取当前状态；`GET /attempts/{id}/events?after=cursor` 通过 SSE 恢复事件流；`GET /tasks/{id}/artifacts` 返回清单与摘要；`GET /tasks/{id}/reader` 返回阅读能力和大数据资源 URL；`GET /attempts/{id}/chunks?cursor/seqs=...` 分页读取块；按能力开放单块重译、源码切片、收藏和位置保存。保留 `Idempotency-Key`；重复键必须校验请求指纹，完全相同请求返回既有操作，不同载荷返回冲突。活动任务去重由明确结果类型返回，不以错误字符串正则提取 id。

事件 envelope 包含 `schema_version`、`event_id`、`task_id`、`attempt_id`、`attempt_seq`、`type`、`occurred_at` 与类型化 `data`。`attempt_seq` 在单次 attempt 内严格递增，重试不沿用前轮事件水位；列表版本使用 `revision` 或 `updated_at` 的强序语义。事件推动 UI 更新通知和段落变更；快照可从持久状态恢复，重放仅提供游标之后事件。日志作为可选低保真诊断流，块结果和产物仍通过可分页 HTTP 资源读取。浏览器单一用户级流发布任务与 attempt 摘要变化；Zotero/CLI 可轮询同一状态资源或消费对应流。

阅读 API 返回 `availability`、`view`、文档 id、内容摘要、版本化 URL、alignment/chunks 引用和明确 `capabilities`。`done`、`partial`、`fault` 是执行状态；可读性与可下载资源分别表达。文件继续使用授权白名单、SHA-256 与不可变 URL，身份凭据应可覆盖 API、SSE 和文件读取。

前端保留 SolidJS 与 pdf.js/pdfslick；引入 Solid Router 处理路由与深链，引入与 Solid adapter 配套的 TanStack Query 统一列表、详情、引用和设置等服务器状态，使用标准 query keys、分页、失效和 mutation 回执。阅读位置、选择、悬浮卡、双栏导航、主题等留在组件或明确 client-state controller。SSE 只负责失效相关查询或按 attempt 更新有限实时状态；不再建立自有 `TaskLive` 数据库来复制服务器账本。TanStack Query 不负责 PDF 对齐或高频光标状态。

首期继续 SQLite WAL，保留本地单机包易启动和离线工作。定义持久化仓储与作业派发端口，任务行创建和 enqueue 意图在同一事务持久化，由进程 dispatcher 认领；此步骤解决当前 HTTP 路由写 SQLite、随后单独 `runner.enqueue()` 的队列内存所有权问题。工作进程可继续在本机运行但应使用 task claim/lease，服务与 worker 分进程需由需求决定。提供替代 PostgreSQL + Procrastinate adapter 的运行模式，复用同库事务提交任务与作业、多个 worker 用行锁认领。选择 PostgreSQL 模式的触发条件是实测 SQLite 写锁/单机副本限制、并发任务或多节点部署需求；迁移数据仍可导出成通用格式。Procrastinate 不是数据库抽象层，作业 ID、重试/中止/重投递状态与任务 attempt 映射必须封装在适配器内。

暂不采用 Temporal。它提供持久化工作流与活动重试，但将工作流代码确定性、历史兼容、独立服务可用性纳入产品承诺。仅当真实失败统计证明 worker 重启恢复、长等待和补偿流程经常由现有阶段哨兵/任务轮次无法可靠解决，并且运维团队接受 Temporal 服务后，再开展独立原型。不要以通用“可靠性更好”作为替换队列的证据。

将本机任务工作目录和开发/单用户交付物放在本地存储端口下，服务器模式可替换 S3 兼容对象存储。产物路径不进入外部客户端协议，只发对象 id、版本、摘要和有时效的授权 URL。SQLite 模式需要本地文件存储，PG 多节点部署必须配共享对象存储或明确单主 worker 约束。输入源解包及编译隔离继续依赖既有安全闸与独立进程。

## 考虑过的替代方案

- 保持所有模块不变，仅新建客户端 API helper：无法移除任务/轮次/产物语义混杂与无 schema 的 wire 契约。
- 以 Node/TypeScript 作为唯一后端：需重写 TeX 展开、翻译与校验、编译修复、安全解包及数据生态，缺乏可覆盖行为等价的收益证据。
- 将 pipeline 抽象为微服务或步骤 DAG 引擎：当前执行主要是单机论文工作目录上的阶段链，跨服务状态/字节传递与分布式补偿会增加接口和运维成本；先用 Python 内部端口降低依赖方向复杂性。
- 上 React/Next.js：PDF 阅读器是 SPA 客户端工作台，没有 SEO、服务端渲染或 Server Component 的已知收益；转换框架不能自动解决服务端状态契约。
- 全面替换 SQLite：本地单用户包需要零服务部署；现有数据库约束和数据迁移可先保留，只有出现多 writer/多节点需求才需要 PostgreSQL。
- 在当前使用规模引入 Temporal：职责超出当前证据支持范围，需评估服务运维、工作流版本演进和重复副作用风险。
- 将段落文本、PDF 页或论文内容塞进事件：事件持久化与重放成本会随产物体积增长，浏览器阅读也不需要事件传输全部文档。

## 验收条件

- 代码依赖图显示 Web/REST/CLI 只依赖应用契约；pipeline 不导入 `server`、CLI 或 web 类型。
- CLI mock/真实本地、FastAPI worker、benchmark 对相同源和配置调用同一 `PipelineRunner`；业务阶段结果对齐，以冻结 corpus 上的状态、译文块、产物检查、编译判定和资源限制作为基准。
- 生成客户端数据类型不漂移；OpenAPI 中每个 JSON 请求/响应、分页、错误码和生命周期动作都有 schema，SSE 事件有独立可校验样例。
- 幂等建任务、同参数复用、同轮重试并发、取消/worker 关停、崩溃后重投递、迟到事件、事件缺口和重复事件均有可重复的状态机测试。
- 刷新、断线重连和多标签页场景通过浏览器端到端测试；同一 task 的新 attempt 不消费上一轮终态；partial 任务已有可读 artifact 仍可打开。
- SQLite 本机部署保持单命令启动、重启恢复和数据升级；PostgreSQL 模式完成多 worker、并发认领、事务性 enqueue、租户隔离、对象读取和备份恢复的集成测试后才宣传支持。
- 只有行为等价基准、资源账本和端到端路径通过后才删除兼容 API/旧表；用户文档、服务契约、代码注释及升级指南同步更新。

## 风险

目前工作树含多个未提交功能文件，研究报告的哈希与数量只描述生成当时的代码树。代码量统计、命名与静态 import 不能替代调用图、数据流、线程亲和与发布部署分析；证据脚本明确为审计基线，不是复杂度评分。

现有持久记录包括付费译文、用户阅读位置、收藏、缓存和产物；版本库存在直连对象、源树副本和旧 API 消费者。新旧 schema 需要可恢复、分步升级和旧版并行窗口，不能一次清空重建。缓存键、share 交换格式、已有 CLI、Zotero、hjfy 兼容接口和 BYOK 头都已有消费者或历史承诺，需要逐个划定冻结与弃用策略。

先引入 Solid Router/TanStack Query 会改变状态更新和生命周期，须对照现有选区/导航同步/资源释放测试；PDF.js/pdfslick 的底层版本和实例限制继续由适配层承担。多客户端身份若采用 Cookie，需同时设计 CSRF、Origin、跨站 SSE、下载 URL 和 CLI/Zotero 认证，模型服务凭据不能继续充当应用会话凭据。

API schema 完整化可能暴露以前只靠前端猜测或服务端容错实现的行为差异。要求向后兼容时采取 add-only 迭代、新 API 命名空间、清晰版本策略和 wire contract tests；认证、任务状态、产物能力及错误语义在客户端共存期间不可悄然改变。

Procrastinate + PostgreSQL 适合已有 PG 运维能力且需要同库 transactional enqueue 的部署形态；在单机 SQLite 模式，它不解决主要产品需求。对象存储引入上传完成、内容校验、孤儿 GC、访问签名和本机路径兼容责任。Temporal、S3 和远程 PostgreSQL 均须在需求触发时分别立项，不作为默认拓扑。
