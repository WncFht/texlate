## 3. 总体方案

### 3.1 双轨并行

- **A 轨 水合（免费，后台常开）**：skeleton → hydrated。瓶颈是抓取带宽不是钱；磁盘水位闸兜底。
- **B 轨 付费波次**：已水合格过 soak 六段。每波后固定修复窗口：qc_replay 回放本波 → sig census → top-N 签名蒸馏成 fixloop 规则/管线补丁 → 下一波先重跑上波失败格（字节闸下免费段零成本、无字节格自动 ABSENT 重跑）。

### 3.2 A 轨水合——密度分发

| 通道            | 触发条件             | 机械                                               | 速率      |
| --------------- | -------------------- | -------------------------------------------------- | --------- |
| IA chunk tar 流 | 同 chunk 待取 ≥12 篇 | corpus_v3 fetch_one→scan→member 提取               | 批量主力  |
| TIGER HF        | IA 无覆盖            | `huggingface.co/datasets/TIGER-Lab/arxiv-latex-5T` | 兜底      |
| arxiv_eprint    | 稀疏格（<12/chunk）  | corpus_expand `acquire_source`                     | ~85 篇/天 |
| scholarweave    | e-band 覆盖格        | corpus_sw 通道                                     | 补充      |

驱动件：`bench/py/specs/corpus_hydrate.py`（开工清单 #3）。水合顺序始终对准下一波名单。

每波跑法：`bench run soak --jobs 32~40 --detach`（>30min 一律脱管 + run.log 直写 + 文件面监控）。regen 格走 `--allow-regen --sel <名单> --yes`。**断线续跑禁 `--resume`**（lost 墓碑被当终态 → accounting BROKEN 实证）；一律开新 run，dedup 逐格验字节自动认回旧工量。

**每波前置清单**：① `env $(cat ~/.config/texlate/bench.env)` 入环境；② `~/.local/share/texlate-bench/vault/.verify-stamp.json` ts <24h（否则 `bench vault verify --level stat` 刷新）；③ `locks/AUTH_DEAD` 不存在；④ detach.lock 空闲；⑤ df >80G。

### 3.4 检验通道——先判后删

老格不凭旧 verdict 免检。`tools/qc_replay.py` 全量回放（变体泛化后覆盖 `-` 域老胞），输出三层名单：

| 判定      | 去向                                           |
| --------- | ---------------------------------------------- |
| pass      | evict 候选（源文件可回收）                     |
| warn      | 留档观察                                       |
| hard/fail | regen 名单，`--allow-regen --sel` 并进付费波次 |

**顺序约束**：回放吃 splice/pdf 字节；splice 缺失的格要用 lake 源文件重编译才能判。所以 evict 只能在回放判完之后执行——先删源文件会造出「质量无从考证」死角。

### 3.5 磁盘策略——clean 格源文件回收

| 层                | 处置                                                                | 理由                        |
| ----------------- | ------------------------------------------------------------------- | --------------------------- |
| vault zh+主干 pdf | **保留**                                                            | 产品本体                    |
| lake 源文件       | **layoutqc-pass → evict**（快道格）/ raw_only 折叠（eprint 慢道格） | 大头：~8MB×12k≈100G，可再拉 |
| state 检查点      | 低优先，后续可清                                                    | zh 入库后续命价值已尽       |
| runs 工作树       | prune 既有规则                                                      | clean 格无付费字节整树清    |
| ledger            | 永不删                                                              | 唯一真相                    |

执行件：`bench lake evict-done`（开工清单 #2）+ `TEXLATE_BENCH_MIN_FREE_GB` 水位闸进 `lake.hydrate` 抓取路径。

### 3.6 网关与重试口径

- 网关：devin-2api（archbox:3033 直连；本机 shim :3003 同实例）+ swe-2-medium，bg token。
- 实测模型：单请求 2.9s 固定 + 13.3ms/out_tok；上游全局约 550 out_tok/s 上限（随窗口浮动，09-27 实测 400–480）。「`--jobs` 8–16 即吃满」**已证伪**：09-27 勘出 `--jobs` 默认 4 才是隐性天花板（4 管线只占约 5 付费槽 ≈40 tok/s）；`--jobs 32`→约 50 槽、40→64/64 槽满，吞吐约 100 篇/h 触上游壁。判活三件套=心跳+events 新增+xlat 出活；网关查量用 devin-2api.db `logs` 表（**time 列是毫秒 epoch**，秒级过滤会静默返回全量）。
- 429：retryable + Retry-After（body `error.retry_after`→header→`3^attempt`≥5s）；缺口=max_tries=5 封顶 → 开工清单 #1 补 param 拉到几十。
