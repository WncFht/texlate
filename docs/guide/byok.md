# 自带 API key（BYOK）

TeXlate 不捆绑模型服务：翻译请求发给你自己的 OpenAI 兼容端点——可以是 DeepSeek、OpenAI、Anthropic、Qwen 这类服务商，也可以是任何自建的兼容网关。三件事依次是 key 配在哪、端点要满足什么、配置之后的行为。

## 三种配法与优先级

| 配法        | 在哪配                                                                                        | 适用                                      |
| ----------- | --------------------------------------------------------------------------------------------- | ----------------------------------------- |
| Settings 页 | `#/settings` 表单，存进数据目录的 `settings.json`                                             | 日常默认，存一次长期生效                  |
| 环境变量    | `TEXLATE_BASE_URL` / `TEXLATE_API_KEY` / `TEXLATE_MODEL` / `TEXLATE_DIALECT`                  | 不落地配置的启动覆盖、容器与脚本          |
| 单次请求    | 首页高级选项的「临时 API Key」，或 `run --server` 的 `--api-key/--base-url/--model/--dialect` | 临时换个 key 或端点跑一次，不写进任何配置 |

同一字段三处都配时的生效顺序要分两半看：key 是「请求头 > Settings > 环境变量」；base_url、model、dialect 是「请求头 > 环境变量 > Settings」——环境变量是部署者的覆盖手段，能整端盖掉界面里的配置。

key 的存在范围按配法收敛：单次请求的 key 只随任务生命周期留在内存，不进 Settings、任务记录、产物和日志；Settings 里存的 key 文件权限 0600，接口回读时只给「已配置/未配置」，永远不回显本体；日志对 key 形态统一脱敏。换端点时每个端点各自的 key 会被记住（按 base_url 分槽），切回来不用重填。

## 端点要求

端点只要是 OpenAI 兼容即可：能接 `POST {base_url}/chat/completions`（或其他方言对应的端点）并返回标准形状。base_url 写站点根或带 `/v1` 都行，校验规则是：不允许在 URL 里嵌用户名密码或 query 参数；非本机地址必须用 https（仅本机回环与 tailnet 主机——`*.ts.net` 域名、`100.64.0.0/10` CGNAT 段地址——放行 http）。

方言（dialect）告诉客户端按哪种 API 形状说话：`auto`（缺省，按端点域名推断——Anthropic 域名自动走 messages 方言，其余按 openai）、`openai`、`anthropic`、`responses`。自建网关按它实现的 API 形状选；推断错了就在 Settings 或 `TEXLATE_DIALECT` 显式指定。

Settings 保存时会拿你的 key 探一次端点的模型清单：配的模型不在清单里会出警告（仍然保存——清单探活失败不阻塞，但模型名拼错会让之后每个任务在翻译阶段失败）。离线环境用 `TEXLATE_MODEL_PROBE=0` 关掉这个探活。

## 多端点档案与自动回退

Settings 页下方的「端点档案」卡面（存进数据目录的 `endpoints.json`）可以存档多个备用端点：卡片以 `model(redirect)` chips 展示模型清单，「编辑」开右侧抽屉分「基本 / 凭据 / 模型」三节管理。每条档案有 base_url、方言、启用开关，凭据二选一——内联存 key（与 Settings 同等保护、永不回显），或填 `key_env` 存一个环境变量**名**（值在环境里读，轮换 key 只改环境不改档案）。手改 JSON 也行，格式是 `{"version":1,"profiles":[…]}`——`models` 条目一律 `{"model":"本地名","redirect_model":"线上名"}` 对象（`redirect_model` 可空串，裸字符串条目不收）；写坏的文件会被改名隔离成 `endpoints-invalid-*` 而不是让服务起不来，含非法条目的档案按坏成员读径整档丢弃。

「模型」节是行式表格：每行一个模型名加可选的「重定向目标」——填了重定向后档案里展示的是本地名、发给上游的是重定向名（卡片上以 `本地名(重定向名)` 显示），适合给上游长名起本地短别名。表格头排有「获取模型」（从端点拉模型清单勾选入档）、「添加模型」、「导出模型」（复制成文本）；勾选行后出批处理条：转小写、去来源（剥 `vendor/` 前缀）、删除选中。档案顺序即回退顺序，卡面下方「排序」弹窗拖拽调整。

档案的用途是**自动回退**：主端点翻译失败时按「活动端点的其余模型 → 各启用的备用端点首模型」顺序换臂重试（臂名一律发重定向后的线上名），单块最多 4 条备选臂，每次切臂在任务警告里留一条 `endpoint_fallback` 痕。三条硬边界：单次请求带来的临时 key 绝不发向备用端点；你自己的 key 也绝不发向 base_url 不同的端点——备用臂走它自己的凭据，没有凭据的远程端点直接跳过（回环端点无 key 合法）；`TEXLATE_MODE=server` 部署形态下回退链整体关闭，档案 API 也整面 403——多端点拓扑由部署方管理。

「探测」按钮（或 `texlate endpoints test <id>`）开测试弹窗逐模型跑两段行为探针：先取模型清单验通端点，再对所选模型发真实会话验行为——`usable` 表示该模型保住占位符且能产出中文，`no_cjk`/`placeholder_lost` 这类判定意味着它不适合做翻译臂；子集探测只刷新被测模型的判定，其余模型的历史判定保留。命令行面还有 `texlate endpoints list`（档案总览）与 `texlate endpoints activate <id>`（把某条档案设为活动端点写回 Settings——激活写入的是重定向后的线上名，主路径直接可用）。

## 模型与参数选择

Settings 的服务商下拉给了几个预设端点与推荐模型作起点（DeepSeek `deepseek-chat`、OpenAI `gpt-4o-mini`、Anthropic `claude-haiku-4-5`、Qwen `qwen-flash`），选「自定义」可填任意端点与模型名。挑模型的实用口径：翻译按段落切块逐块调用，一篇论文几百次请求，**指令遵循稳定性比峰值聪明更重要**——模型必须原样保留占位符（公式、引用、宏都被替换成了占位记号，模型只翻 prose），守不住占位符的模型会让校验器重试或回退原文。中端模型通常足够，推理型模型的长思考对段落翻译收益小、耗时大。

其余可调项：并发（1–16，缺省 3）控制任务内并行请求数——遇到限流（429）先把它调小；目标语言 zh-CN/zh-TW/en；术语表粘贴自定义对照表约束译法；「上下文提示」给每块带上标题等上下文，多数端点开着更好。

## 未配 key 的降级行为

不会跑死，会降级：没有可用 key 时翻译臂回落到 mock——产出一份结构和长度都对的中文 PDF，但每段是固定占位文本，界面上也有提示。它是链路自检的兜底产物。要让缺 key 直接报错，设 `TEXLATE_TRANSLATOR=gateway`（此时缺 key 直接失败退出）。

## 断点续翻与缓存

翻译是逐块记账的：每翻完一块就写缓存，任务取消、服务重启、中途崩溃都不丢已译部分，重试接着断点翻。译文缓存按「原文块 + 模型 + 提示词版本 + 语言」内容寻址——同一篇论文同一配置重跑直接命中，秒回不烧配额；换模型是另一组键，不会串译文。

单机形态下缓存默认全局共享。多用户部署（`TEXLATE_MODE=server`）默认也跨用户共享译文缓存——公开论文的翻译结果是确定性内容，共享是省钱的；但它同时是个存在性侧信道（能探出「别人是否译过某篇」），要避免可设 `TEXLATE_CACHE_SCOPE=per_key` 按 key 分桶，代价是命中率按凭证碎片化。

`needs_auth` 是唯一的缓存例外：用单次请求 key 建的任务在重启后变成 `needs_auth` 等补 key——key 不落盘是刻意的，服务端重启后拿不到它，页面上重新填一次即可续跑。

## 限额

Settings 里的 `quota_max_tasks` 与 `quota_max_bytes` 给 server 形态限总量（0 为不限）；`concurrency` 上面说过是任务内的请求并发。任务级并发固定为一——队列一次只跑一篇论文，其余的排队等。
