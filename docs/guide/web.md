# Web 服务与阅读器

`texlate web` 启动一个本机服务：浏览器界面提交论文、看实时进度、双语对照阅读、下载产物，命令行的 `run --server` 也把任务提交到这里。任务是队列制的——同一时刻只跑一篇，其余排队，每篇内部按并发设置并行调模型。

## 启动

```bash
uv run texlate web            # http://127.0.0.1:8765
uv run texlate web -p 9000    # 换端口
```

需要 `uv sync --extra server` 装的服务端依赖。数据目录缺省是主目录下 `.texlate/`（`--data-dir` 或 `TEXLATE_DATA_DIR` 改）。本地形态有单实例锁：已经有一个实例在跑时，再执行 `texlate web` 会直接打开浏览器指到那个实例并退出，不会报端口冲突，也不会起第二个进程抢同一个库。

图形界面是构建产物、不随仓库带。没构建过前端时服务照常提供 API——`run --server`、curl 都能用，浏览器里则没有页面。构建一次即可：

```bash
scripts/build-web.sh
```

服务日志落在 `<数据目录>/logs/texlate.log`（DEBUG 级、自动脱敏、4MB×3 轮转），排查问题时先看它。

## 首页：提交任务

首页一个输入框加一个上传按钮，下方是选项表单（默认收起，分常用与高级两组）。

输入框接受 arXiv id（新旧式、`vN` 钉版、arXiv 链接都行），打字时会给候选补全。提交后立刻跳到任务页看进度。同一篇论文同一套配置重复提交不会重跑——命中已完成任务直接复用产物；高级选项里的「prefer」切到 `fresh` 可强制重跑。

上传按钮（或直接拖拽文件到页面）接受四类材料，按文件内容自动识别路由：

| 材料                                          | 处理                                                                          |
| --------------------------------------------- | ----------------------------------------------------------------------------- |
| `.tex` / `.tar` / `.tar.gz` / `.tgz` / `.zip` | 本地 LaTeX 工程，走与 arXiv 相同的翻译编译链                                  |
| `.pdf`                                        | 经 babeldoc 侧车翻译（需要先 `pipx install babeldoc`，不装则上传 PDF 报 501） |
| `.docx` / `.epub`                             | 双语插译——产出每段原文后跟译文的同格式文档                                    |
| `.share.zip`                                  | 别人分享的译文缓存包，导入后直接重建产物                                      |

上传上限：单文件 80MB，解包后合计 300MB、4000 个文件以内。

任务选项分两层。常用层：模型、目标语言（zh-CN/zh-TW/en）、编译引擎（auto/xelatex/tectonic）、并发（1–16，任务内并行调模型的请求数）、上下文提示开关。高级层：前置内容开关（摘要/标题/作者，缺省翻摘要和标题）、`prefer` 缓存策略、取源通道（e-print 源码链 / arXiv HTML 降级链——源码不可得或解析失败时可换 HTML 通道）、完成后自动打共享包、主文档文件名、单次任务的术语表与一次性 API key（只用于这次提交，不写进 Settings）。

没配 key 也能提交——产出的是占位译文（见 `byok.md` 的「未配 key 的降级行为」），界面会有提示。

## 任务页

`#/tasks` 列出全部任务：标题、状态、进度、时间，支持搜索与按状态筛选，可以单条打开、取消进行中的任务、重试失败任务、删除任务及其产物，也能批量清理。

## 任务状态

一个任务按 `queued → fetching → parsing → translating → compiling` 走，终态有六种：

| 终态          | 含义                                                      | 怎么办                                          |
| ------------- | --------------------------------------------------------- | ----------------------------------------------- |
| `done`        | 完整出 PDF，全部块翻完                                    | 直接读                                          |
| `partial`     | 出了 PDF 但有降级：部分块回退原文、或修复后有残余警告     | 照常可读，横幅里写明降级点；想重试点重试        |
| `fault`       | 失败（取源/翻译/编译链走尽）                              | 面板里有错误码与原因；修好环境或换 key 后点重试 |
| `cancelled`   | 用户取消的                                                | 已译的块保留，重试复用不重复消耗配额            |
| `interrupted` | 服务重启时任务还在跑                                      | 点重试从断点续跑                                |
| `needs_auth`  | 任务用的是一次性 key（请求头传入），重启后 key 不在服务端 | 在面板上重新填 key 再重试                       |

断点续跑是逐块的：翻好的块进缓存，重试只翻没完成的。进程被杀、机器重启都不会丢已完成的进度。

## 阅读器

任务完成自动进阅读器。三种视图：原文 / 译文 / 双语对照（分栏）；arXiv 任务还有第四档「导读」。对照模式下两侧滚动同步（可关），可以左右交换两栏、缩放（适应页宽/整页/百分比）、按页跳转、文内查找。窄屏设备缺省单栏译文视图。

阅读位置自动保存——关掉页面下次打开回到原处，模式、缩放、同步开关等偏好也随之恢复。

对照模式下的双语对位是句级的：悬停或点击一句，另一侧对应句即时高亮；跳转落定对侧句子有对位闪示。点正文中的引用标号弹出文献悬浮卡——「跳至引用目标」「翻译此文」（把该文献也翻译成中文任务）、「查找引用」（反查全篇引用该文献的位置）、复制条目、打开 arXiv/DOI/alphaXiv 等都在卡面或右键菜单里。

选区有统一命令面：选中文字出浮动条，右键出上下文菜单，快捷键走同一注册表——复制、复制双语对照、文档内查找、公式/选区「复制 LaTeX 源」等。按住修饰键（macOS ⌘ / 其他 Ctrl）进入检视层：页面上的可交互元素浮现高亮，修饰键 + 点击就地 peek。

主题跟随系统，也可在 Settings 固定纸张主题（亮 / 暗 / onedark）；暗色下 PDF 走图元级改色而非整图反相。

顶部菜单下载产物：中文 PDF（`zh.pdf`）、原文 PDF（`en.pdf`，由原文源码本地编译得到、源不可编译时缺席；PDF 上传任务则为上传的原文件）、对照数据（`dual.json`）、文献表 `.bib`、翻译后的 LaTeX 源码包（`zh-src.zip`）、编译日志等；上传的 docx/epub 任务则是双语版文档直链下载。arXiv 任务完成后还有「分享本译文」按钮，把译文打成 `.share.zip` 共享包（详见 `export-share.md`）。

## 发现页

`#/discover` 聚合 alphaXiv 的公开榜单与搜索：按热度/浏览/点赞/GitHub/评论/近期排序，时间窗从 3 天到全部，点论文卡可跳回首页预填 arXiv id 直接翻译。这是机会型增强——上游不可达时页面整块隐藏或报可重试错误，不影响翻译主链路。

## Settings 页

`#/settings` 配置 BYOK：API key（只写不回显，页面上只显示「已配置/未配置」）、服务商预设（DeepSeek、OpenAI、Anthropic、Qwen、自定义 OpenAI 兼容端点）、base_url、模型、方言、目标语言、编译引擎、并发、上下文提示、术语表。「测试」按钮按当前表单值探活端点（含未保存的改动），「清除已存 Key」把服务端存的 key 删掉。细节与三种配法的优先级见 `byok.md`。

页面下方还有主题（跟随系统/浅色/深色）与界面语言（自动/中文/English）两个本地偏好，只存在浏览器里。

## 多用户部署（TEXLATE_MODE=server）

缺省的 local 形态假定只有你本机可达：API 不带鉴权，靠回环对端 + Host 头检查挡住外部直连与 DNS rebinding。所以**不要把 local 形态绑到非回环地址**——CLI 会明确警告：可达网段内任何人都能建任务、改 Settings、读产物。

要部署给多人用：

```bash
export TEXLATE_MODE=server
uv run texlate web --host 0.0.0.0 -p 8765
```

server 形态下所有写操作要求 `X-Texlate-Key` 请求头（服务端的 key 不外借给匿名请求）；跨域前端需要把来源加进 Settings 的 `cors_origins` 白名单，否则浏览器同源策略直接拒绝。多副本部署不再有单实例锁，`python -m texlate.server` 是不经锁的低层入口。配额面（`quota_max_tasks`/`quota_max_bytes`）与产物保留期（`retention_days`/`retention_max_gb`）都在 Settings 里配——保留期到期或超容量的终态任务会被自动清除。
