# 常见问题

按「遇到什么情况」组织。每条先给结论再给操作；环境类问题先跑 `texlate doctor` 对照一遍。

## 编译失败了怎么办

先看终态：`partial` 表示出了 PDF（有部分降级，比如个别段回退原文或带残余警告），可以直接读；`fault` 才是真失败。面板里的错误码和编译日志（产物清单里的 `compile.log`）说明失败点；把日志最后几十行和任务 id 一起报 issue 最有用。

想再试：点任务面板的重试，或 CLI 用同参数重跑——已翻好的块走缓存不重复烧配额，重试从断点继续。编译链死在某一步时，在选项里手动换引擎（xelatex ↔ tectonic）往往能过：两者对宏包和字体的覆盖面不同。

## fixloop 是什么

编译失败时的自动修复循环：读编译日志 → 给错误分类 → 按规则库逐条修源码或环境 → 重编译，直到出 PDF 或规则走尽。进度显示里的 `rN ...` 轮帧就是它在干活。它处理的是 arXiv 论文的常见坑——缺宏包、旧式 LaTeX 写法、字体问题、嵌套打包等；走尽了才报 `fault`。想关掉它用 `TEXLATE_NO_FIXLOOP=1`（不建议，关掉后失败率明显上升）。

## 离线能不能用

一半能。`--offline` 或 `TEXLATE_OFFLINE=1` 把取源切成纯本地：已缓存的论文照常解析、编译、出 PDF——没缓存的报 `offline_no_cache` 退出 1，不会偷偷联网。翻译环节始终要模型端点；端点是你本机或内网的自建网关时，外网断了也照翻。

## 支持哪些 arXiv 论文

新旧式 id 都认，含 `vN` 版本钉版和 arXiv 页面/abs 链接粘贴。前提是论文有 LaTeX 源（e-print）——绝大多数有；作者只传了 PDF、或源码缺得没法编译的，可以试两个降级通道：任务选项里的 `html` 取源通道（走 arXiv 官方 HTML 版），或者干脆把 PDF 上传给 babeldoc 侧车（需要先装 babeldoc）。已撤稿（withdrawn）论文的 e-print 只剩占位文本，不算可翻译对象。

## 译文是占位文本是怎么回事

没配 key：翻译臂回落到 mock，每段中文是固定占位文本——链路自检用的兜底。配好 BYOK 再跑就有真译文（`byok.md`）。确认是否配上的最快办法：`texlate doctor` 的 gateway 一行，或 Settings 页看「已配置」。

## 并发与速率怎么算

两个旋钮别混：任务级并发固定为 1——队列一次只翻一篇论文，多提交的任务排队；任务内的 `concurrency`（Settings 或任务选项，1–16，缺省 3）是这篇论文内部并行调模型的路数。撞限流（429）先把 concurrency 调小；端点限流是瞬时的，客户端自己会退避重试，真持续失败才需要换端点或降并发。

arXiv 侧的取源也做了礼貌限速与退避；批量跑大量论文时让任务排队自然消化即可。

## 数据都存在哪

两类位置：

- 数据目录（`TEXLATE_DATA_DIR`，缺省主目录下 `.texlate/`）：任务库与每任务产物（`tasks/t_*/`）、`settings.json` 与 `connections.json`（0600，key 在这里）、`logs/texlate.log`、`share/` 共享包发布目录、`tools/` 托管引擎。备份或迁移整个 `.texlate/` 就行。
- 源缓存（缺省主目录下 `.cache/texlate/src/`，`fetch --cache` 改）：arXiv e-print 钉版原样存档——删了只是下次重新下载。

产物会无限涨：Settings 里的 `retention_days`（保留天数）和 `retention_max_gb`（容量上限）控制自动清理，缺省 0 = 不自动清，自己删 `tasks/` 下的目录或在任务页点删除都可以。

## 上传有什么限制

单文件 80MB、解包后合计 300MB / 4000 个文件。LaTeX 工程（`.tex`/`.tar`/`.zip` 等）走翻译编译链；`.pdf` 走 babeldoc 侧车（`pipx install babeldoc`）；`.docx`/`.epub` 走双语插译；`.share.zip` 导入共享译文。

## EPUB 报「受 DRM 保护」是什么意思

带数字版权管理（DRM）的 EPUB 会被直接拒绝——规避技术保护措施在多数司法辖区违法，这个检查没有开关。字体混淆不算 DRM（那是出版商对嵌入字体的常规处理），能正常翻。去掉 DRM 后自用的书能不能翻取决于你所在地的法律，请自行判断。

## 多用户部署要注意什么

`TEXLATE_MODE=server` 起多租户形态：所有写操作要求 `X-Texlate-Key` 头，前端跨域要把来源写进 `cors_origins` 白名单。缺省的 local 形态不要绑到非回环地址——API 无鉴权，绑了等于把建任务和改配置的权限开给整个可达网段（启动时 CLI 会警告）。配额、缓存隔离、保留期的细节分别在 `byok.md` 与 `web.md`。
