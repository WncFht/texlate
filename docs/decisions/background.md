# 项目缘起：从 hjfy.top 到 texlate

> **状态**：现行
> **日期**：2026-09-14（立项）| 更新 2026-09-20（文档库迁移）

texlate 是「幻觉翻译」（hjfy.top）的开源复刻：输入 arXiv ID/URL，取 LaTeX 源码做段落级 LLM 翻译，注入中文支持后重新编译出中文 PDF，前端双语对照阅读。内容：复刻对象、原作者已验证的结论、texlate 的复刻目标与差异化——全部 ADR 的问题背景。

## 复刻对象 hjfy.top

hjfy.top 是吴多益（amis 前端框架作者）2025 年上线的 arXiv 论文中译服务[^hjfy-site]。产品形态：用户提交 arXiv 链接，服务端产出一个双语对照阅读页，可下载原文 PDF、译文 PDF 与译文 LaTeX 源码包三件套；已翻译的论文匿名可看；免费模型翻译，每日新建配额 100 篇；微信/手机号登录。作者自述定价内测免费、后续将收费[^wuduo]。

作者原文给出的关键结论，texlate 全部沿用[^wuduo]：

- **四种方案取舍后走 LaTeX 源码路线**。候选包括 PDF 直翻、arXiv HTML、e-print 源码编译等；最终选定取 e-print LaTeX 源码、翻译后重新编译，因为只有源码级处理才能保住公式、引用、版式，PDF 直翻的效果作者自评很差。
- **LaTeX 只能半解析**。LaTeX 是图灵完备的宏语言，完整解析等于重写 TeX 求值器；hjfy 的做法是自研「够用」的半解析——能识别结构、保护不可译元素，而不是求出完整 AST。
- **幻觉检查是必要层**。LLM 会丢失、改写、编造占位符与命令，译文必须经过独立校验，不能让损坏内容进编译。
- **编译失败率是最大工程壁垒**。作者对 5000+ 篇论文做人肉修复迭代，才把编译错误率压到 ~5%；这部分经验沉淀在一个私有修复库里，是 hjfy 相对开源同类（成功率不足 60%）的核心差距。
- **按引用数选 1 万篇高引论文做预译**。批量获取走 arXiv S3 requester-pays 桶，语料内引用计数排序，命中即秒回。

## texlate 的复刻目标

复刻目标是**同形态、开源、可复现**的实现。与 hjfy 的对位关系：

| 维度     | hjfy.top                    | texlate                                |
| -------- | --------------------------- | -------------------------------------- |
| 开源     | 闭源                        | Apache-2.0                             |
| 模型     | 固定便宜模型 + 反馈换档重翻 | BYOK 任意 OpenAI 兼容端点              |
| 编译修复 | 人肉固化私有库（黑盒）      | yaml 规则库可贡献 + LLM 修复器（白盒） |
| 译文缓存 | 平台预译 1 万篇             | 本地三层缓存 + 用户 opt-in 共享包      |
| PDF 通路 | 开发中                      | BabelDOC sidecar（现成方案）           |
| 价格     | 内测免费 → 将收费           | 永远免费（用户自付 LLM 成本）          |

差异化增量（hjfy 没有的）：EPUB/DOCX 双语插译导出、yaml 修复规则库社区众包、LLM 自动修复器、全链白盒可复现的 benchmark 体系。

## 复刻方法论：先调研实证，后裁决冻结

动工前做了约 20 项子调研/实验（`docs/05` 证据矩阵 E1–E22——`docs/0x` 旧文档已移除，此类引用均为 git 历史指针，检索见下节）：8 个 LaTeX 解析库与自研 spike 的大横评、宏展开语料统计、引擎矩阵双引擎实测、16 篇 mock 端到端管线、fixloop 修复 spike、hjfy 站点侦察、texglot 参考实现精读、成本模型、网关模型横评。每项 pending 决策都带实证结论后，方案于 2026-09-15 冻结为 22 条裁决（`docs/05` §3，同上）。

里程碑按 M0 骨架基线 → M1 展开 + 翻译 → M2 编译攻坚 → M3 产品化 → M4 远期推进。截至 2026-09-20：M0 已验收、M1 实质达成、M2/M3 推进中——解析侧 identity 100%、leak 0.040%（约 3900 文件口径）；编译侧 scorecard 5124 格 union pdf 97.89%、clean 84.99%；real 臂 n200 与 mock 臂打平（union pdf 同 98.5%）。里程碑判定与演进细节见 `log/` 与各 ADR「演变/现状」节。

## 决策记录的组织方式

本目录只收录**裁决**：为什么这么定、证据在哪、后来被什么改判。每条裁决收敛到当前生效的结论（`decisions/adr/`）；被否方案集中登记在 ADR-0019 防翻案；实现细节的唯一事实源在 `spec/`；过程证据在 `research/`。旧 `docs/01–05` 决策史已于 2026-09-20 自工作树移除（5ebc9797），仅存 git 历史——可经 `git show 5ebc9797^:docs/05-reproduction-plan.md` 等检索；本文与诸 ADR 中 `docs/0x` 引用均为历史指针，与 ADR 冲突时以 ADR 为准。
