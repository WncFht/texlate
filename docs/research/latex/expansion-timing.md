# 宏展开时机语料实验 — 即时展开 vs 二遍展开

> **结论**：混合方案成立——扫描中即时建表 + 调用点查表展开，单遍即可，不需要「先建全表再二遍展开」。语料 39 篇 / 44 个主文档中正文级 use-before-def 实测为 0。
> **状态**：时点证据（2026-09-15 口径；结论已落地为 gullet 单遍管线，现行规范见 `spec/latex-pipeline.md`）
> **日期**：2026-09-15

## 1. 实验口径

39 篇语料、44 个主文档（含多 main/双版本）、55 个文档级分析单元。方法：从每个含 `\documentclass` 的主文件展平 `\input/\include/\subfile`（含裸文件名形式 `\input file`），对展平文本做逐字符词法扫描（注释/verbatim/def 体分层），逐宏名比较首个流式调用位置与首个定义位置。

## 2. use-before-def —— 单遍的核心风险实测为零

| 分类 | 宏名数 | 说明 |
| --- | --- | --- |
| 正常序（def < 首用） | 1351 | 单遍展开天然正确 |
| 正文级 use-before-def | **0** | 首用在 `\begin{document}` 后且早于一切定义 |
| preamble 级 use-before-def | 12 | 首用在 preamble、定义更晚 |
| 首用后重定义（redef） | 3 事件 | `\renewcommand` 覆盖——单遍语义与 TeX 一致 |
| 潜伏乱序（外层宏被调用时内层未定义） | 1 | 数学上下文，可见损失 0 |
| 定义但从未在文本流调用 | 3035/4398（69%） | 模板宏集 + LaTeX 内部配置类 renew |

正文级 0 例的含义：对「遇到 `\newcommand` 就登记、遇到 `\foo` 就查表」的单遍管线，正文内没有任何调用会扑空。51% 论文把定义写在 `\begin{document}` 之后（268 个），但全部遵守先定义后使用的线性序——作者本来就按 TeX 的顺序语义写。

preamble 12 例全部良性：一类（5 个宏名）首用在 `\PreprintCoverTitle{\papertitle}` 等未知命令参数内——这些调用无论展开时机如何都会整调用保护，内部宏展不展开无差别，实际损失 0；一类（6 个）是 `\left`/`\right` 的 `\renewcommand`——其前的 `\left` 是原语使用，本就不该按后来的定义展开，单遍「先按原语处理」反而正确；剩 1 个 catcode/`@` 角落 case。

3 个重定义事件反而是单遍的优势：先全量建表（last-wins）会让早期调用拿到晚定义，**顺序单遍才是 TeX 语义**。

## 3. `\if` 族复杂度 —— 结构化配对即可

| 指标 | 值 |
| --- | --- |
| 配对 `\if…\fi` 块 | 61 块 / 10 文档 |
| 带 `\else` | 47 |
| 块内含 ≥20 字符可译 prose | **仅 5 块**（4 preamble + 1 正文死代码） |
| `\newif` 自定义旗标 | 8 个 |

opener 分布：`\ifmmode` 36（几乎全是 `\def\L2{\ifmmode L_2\else $L_2$\fi}` 一族）、`\ifnum` 8、`\newif` 旗标 8、类文件旗标 5、其余零星。含 prose 的 5 块中 4 个是 preamble 包/版式开关、1 个是正文 `\iffalse` 死代码块——**没有任何 `\if` 块把可译正文劈成两半**。结论：条件求值不需要，`\if…\else…\fi` 作结构整体处理即可（`\iffalse` 丢块、已知真旗标留块、未知旗标整段字面或取 else 支）。

实现期发现的两个分类陷阱（已计入扫描器口径）：`\ifb` 不是条件而是物理单位宏（inverse fb）——`\if`+小写名需先查宏表；`\ifAnonymous{T}{F}` 型是类文件定义的**双花括号参数宏**（`\newcommand{\ifAnonymous}[2]{\if@ACM@anonymous #1\else #2\fi}`）——判据「非原语 `\if` 紧跟 `{` 即宏调用」。另有 `\ifthenelse`（花括号条件无 `\fi`）6 次。

## 4. `\def` 定界参数 —— 小但存在

非纯 `#n+空白` 参数段的 `\def`：15 例 / 7 文档（16%）。真定界参数约一半（坐标解析宏 `\def\ra[#1 #2 #3.#4]` 等），另一半是 `\def\@xxx`/`\def\csname…\endcsname` 伪判定。v1 的处置是当 opaque 宏整体保护；v2 gullet 实现了定界参数编译（见 `expansion-design.md` §5）。

## 5. `\input/\include` —— 展平必须做，注意裸文件名

| 指标 | 值 |
| --- | --- |
| 引用事件 | 201（input 174 / include 16 / subfile 11） |
| 嵌套深度 | ≤4（1 层 159、2 层 35、3 层 6、4 层 1） |
| 解析失败 | 0 |
| 注释掉的 `\input` | 8 处 —— 不得展开 |
| `\includeonly` / docmute / standalone / import | 0 / 1 / 0 / 0 |

关键发现是**裸文件名形式**：`\input macros.tex`、`\input grid_1param_result_table`（单文档 20+ 处含嵌套）。只认 `{file}` 形式的展平实现是真实 bug，必须补裸文件名解析（读 `[A-Za-z0-9._/-]+` 至空白/反斜杠）。subfiles 子文档 = 父 preamble + 本体 body，11 个子文档均正确继承父级 ~142 个定义。

## 6. 透明宏率复核 —— 严口径 23% / 宽口径 54%

定义体去控制序列后：连续 prose run ≥20 字符的宏 48 个、覆盖 9/39 篇（23%）；字母总数 >20 的宏 130 个、覆盖 21/39 篇（54%，与早期普查 49% 一致）。两口径差异说明多数「含文本」宏体是 `Figure~\ref{#1}` 这类短词+引用混合，真·整段句子藏宏里约 9 篇。**结论：宏体文本提取仍必要（1/4–1/2 论文受影响），但「≥20 字符连续 prose」作 transparent 判据会漏短词型——保留字母总数口径或降到 ~12。**

## 7. `\makeatletter` 与展开爆炸风险

`\makeatletter` 区：14 区 / 10 文档，长 60–531 字符（中位 ~150），区内 `\def` 合计 15 个——小且无害。

展开爆炸不存在：stream 调用总数 40731（限已定义名）、定义 4398、调用/定义比 ~9.3×、宏体互引 token 1052、**依赖链最深 4 层**（0 层 21 文档 / 1 层 14 / 2 层 8 / 4 层 1）。迭代 ≤5 轮即不动点，无自增/递归宏迹象。

## 8. 决策与接受损失清单

采用混合单遍的理由：正文级 use-before-def 为 0 使二遍的唯一收益场景不存在；重定义场景下单遍才是 TeX 语义；preamble 定义不产生文本输出、前置使用不构成问题；展开量小使调用点展开代价可忽略。补救兜底：展开阶段遇到「当前未知但后来被定义」的宏名记 use-before-def 日志，作新语料回归警报。

| 角落 case | 规模 | 损失 |
| --- | --- | --- |
| preamble 前置使用 | 12 名 / 5 文档 | ≈0（都在整调用保护的未知命令参数内） |
| `\def` 定界参数 | 15 例 / 7 文档 | v1 当 opaque 保护不代参（v2 已实现） |
| `\ifXxx{T}{F}` 双参 if 宏 | ~20 次 / 2–3 文档 | 整调用保护；内层 `\if@` 不求值 |
| 非原语 `\if` 块分支选择 | 5 个 prose 块 | 取 else 或整段字面，最多漏 1 个 `\iffalse` 附录段（本为死代码） |
| `\let` 定义 | 15 例 | v1 未建表 → 调用当未知命令保护（v2 已建别名表） |
| `\input` 于宏体内 | 0 观测 | 不展开记日志（v2 gullet 原生支持） |
| `\includeonly` 过滤 | 0 | 无损失 |
| active-char/catcode/`\halign` | ~1–3 篇 | 已知放弃 |

顺带回输的两个实现修正：`flatten_inputs` 支持裸文件名 `\input file`；`\if` 判定前置查宏表 + 「非原语 if 紧跟 `{` 即宏调用」规则 + `\newif\ifX` 旗标名 token 不入条件栈。
