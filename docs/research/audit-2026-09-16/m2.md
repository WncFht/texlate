## 1. normalize.py 归一化层 — ✅

`src/texlate/compile/normalize.py`（673 行）逐条实现 docs/08 §3.2 清单：comment 终结符（`normalize.py:89`）、float 位置参数（`:104`）、pdfTeX 输出特性/microtype 降级（`:133`）、px→`\pdfpxdimen` 尺寸语境限定（`:171`）、inputenc/fontenc 剥名（`:218`）、`\pdfinfo/\pdfoutput`+驱动选项 pdftex→xetex（`:243`）、OT1/T1/LY1→TU 字体族映射（`:346`，跨文件改写在 `prepare_legacy_latin_fonts`）、legacy CJK→xeCJK/luatexja（`:400`）、bundled .bbl 兜底（`:457`）、`../` 越界 rebase（`:488`）+ 外部路径审计 `source_path_violations`（`:530`）。主编排 `normalize_engine`（`:568`）按引擎分档，`normalize_project`（`:637`）做工程级手术并把非平凡编码判定落 `stats["encodings"]`。

编码 tier 链在 `textutil.py:523` `sniff_tex_encoding`：BOM → utf-16 NUL 密度 → strict UTF-8 → 高字节相邻占比 ≥60% 的 CJK 双字节族 argmax（含西里尔否决，`textutil.py:582-595`）→ 作者声明先验（落后 ≤1 标点级分差即采纳）→ utf-8-mixed 分段 → latin-1 兜底，永不抛（`decode_tex_with:648`）。探针证据 `bench/results/encoding-probe-2026-09-16.json`；aux/bib 同档转码在 `_transcode_aux_bib`（`normalize.py:620`）。

## 4. 沙箱 — ✅（注明 Linux 边界）

`compile/sandbox.py`（237 行）非占位：`child_env` env **白名单**透传 + 强制 `TECTONIC_UNTRUSTED_MODE=1 openin_any=p openout_any=p shell_escape=f`（`:58-77`）；`run_process` 进程组隔离（`start_new_session`）+ 超时 `killpg` 整树杀 + stdin DEVNULL + 输出封顶 8MB 留尾（`:169`）；`sandbox_wrap` macOS sandbox-exec profile（deny $HOME 读 + 全写后白名单放行，`:80-166`）。接线：`engine.py:483,531,537,562,616,829-834`。

边界：sandbox-exec 仅 darwin 生效，Linux 上原样 passthrough（`sandbox.py:94`）——本层在 Linux 的实际隔离 = env 洗白 + kpathsea paranoid + untrusted + 进程组杀，无文件系统级 OS 隔离。run_meta.json 自述口径一致（"sandbox-exec darwin / passthrough linux"）。这与 docs/08 §4.4 规格相符（规格本身就是 macOS sandbox-exec 优先）。

## 8. soul_cjk_mbox — ⚠️ 规则在、覆盖缺口自知

`rules.yaml:851-873`：order 100，`when: soul_err`，regex 把 `\hl\ul\st\so\caps{含CJK参数}` 包 `\mbox{}`，risk: low，双引擎 native/same。**但**：`known_gap` 自承唯一触发格 2005.11401/zh 触发 soul_err 而 regex 0 文件命中 → dirty_pdf，`stats.fires: 0` + "沉淀队列头号 case"。即：规则形态在，实跑零命中，覆盖未验证。

## 9. 出口门「200 篇 ≥90%」— ❌ 未达（差距 0.5pp / 1 篇量级，但口径多重不符）

证据现场：`bench/results/compilebench-v4-2026-09-16/`（baseline 臂）+ `bench/results/fixloop-cbv4-2026-09-16/`（fixloop 臂），同批 corpus_v3 分层抽样 sample.json（n=180，seed 20260915）。

数字链：baseline union pdf 127/180（70.6%）→ fixloop 臂 union pdf **154/172 = 89.53%**（clean 层 149/172=86.6%）。两个口径缺口：

1. **n 不符**：门要 200 篇；实测分母 172（180 样本中 8 篇双引擎 no_main_tex 未进 fixloop 臂）。折算全样本 154/180=**85.6%**（HANDOFF §2.2 同口径）。
2. **链路不符**：fixloop 臂口径自述「直跑，无 normalize/inject 前置」——测的是 fixloop 对原始源码的净收益，**非产品全链**；而产品 `e2e.py` 管线根本未接 fixloop（`compile/__init__.py:10` 自注「fixloop 为独立模块另行交付」），出口门语义上的「编译成功率」严格说尚无对应实测。
3. 另有 §6 记录 7 格回归（baseline pdf~ → fixloop reject:latex209/pstricks_route，属故意拒绝走降级链，产品语义可辩，但 pdf 计数上确实扣分）。

结论：89.5% vs 90% 差 0.5pp ≈ 1 篇——趋势上触手可及，但按字面三项（n=200、≥90%、产品链口径）均未满足，**判未达**。补齐路径明确：normalize+inject+fixloop 全链接线后进 e2e 臂、n 补到 200、reject 类降级链产出计入方式需在 PROTOCOL 里钉口径。
