# 评测存储与恢复经验

本文提炼 2026-09 的存储迁移、去重和修复事故。它保留会影响恢复与清理判断的机制；不保留逐轮排期和全部审计发现表。当前规则见 [bench-trizone.md](../spec/bench-trizone.md)。

## 账与字节不可互相替代

历史恢复将编译失败的 splice 字节封进 vault，kind 与 compile 共域且没有生产者区别时，need/alive 判断持续命中，fixloop 每轮被跳过。表面是“规则救不回”，实际是修复未被执行。增加规则不能修正这种去重状态。

2026-09-25/26 对 103 格显式失效并重放，在不重复模型调用的条件下有 98 格恢复 PDF。历史记录还暴露失败终态再次 harvest 复封的问题；重试协议必须同时核验生产者、判词与资产有效性，不能只检目录和 kind。

另一去重错误把 state-only 元数据当作翻译有效产物，使 35 篇被错误标记 VERIFIED。元数据宣称完成不证明付费译文存在；恢复时 ledger、manifest、摘要与真实文件必须互证。

## 清理与备份

元数据可重放不代表付费字节可重建。lake、工作副本与缓存按再生成本区分；vault 的 zh/splice 不作为免费缓存删。硬链接去重需要按 inode 口径计算释放量，不按逻辑路径累加。

最小备份 tar 只包含账本和元数据时，不能据此宣称可恢复付费产物。迁移前唯一恢复源需要单独保留，不进入普通轮转。恢复完成应检查缺字节、有字节无账、摘要不一致和版本冲突，再允许去重或付费执行。

2026-09 的 ICLR 研究曾丢失工作台账，包括已完成的 id 映射，而下载载荷有部分幸存。暂停不等于可删除；外部 API 工作结果可能比免费 PDF 更昂贵，备份范围应按重建代价判断。该独立研究的恢复信息保留在 `bench/py/iclr/README.md`。

## 诊断与质量

clip 幻影层、图内英文标签和原稿已有 overfull 曾造成质检误报。回放应使用副本、基线和人工核对的正反例，分别报告检测器错误、输入不可用和真实缺陷。降低误报不能以压低真阳性为代价。

修复后的复测记录和原始 run 分离，后验聚合必须说明取最新真实执行还是包含 dedup 行。实验报告只写已观测状态；不能把“补跑候选”“等待放行”长期留作现行工程承诺。
