# Semantic Scholar 数据源调研（2026-09-19 实测）

Semantic Scholar（S2，Allen Institute for AI 运营）对外暴露三层服务：Graph API（实时图查询）、Recommendations API（embedding 推荐）、Datasets API（月度快照批量下载）。本次调研对三个服务的 swagger spec、公开端点、免费样本数据全部做了实测。核心结论：**S2 是当前唯一把「24 亿条带属性引用边 + 1.2 亿条 SPECTER embedding」做成可直接下载数据集的开放数据源**，但实时 API 的匿名配额是全局共享池，实测期间长期处于打满状态，不能当可靠生产依赖。

## 语料规模

官方产品页宣称 **214M papers / 2.49B citations / 79M authors**[^s2api]。与 datasets 快照对照（release `2026-09-17`，实测）：papers 200M 条、citations 2.4B 条、authors 75M 条——产品页数字略新（实时库 > 月度快照），量级一致。

## 一、Graph API：`api.semanticscholar.org/graph/v1`

Swagger spec 公开在 `/graph/v1/swagger.json`（实测 200，123KB），无需鉴权即可读。

### 端点清单（spec 枚举）

| 端点 | 说明 |
| --- | --- |
| `GET /paper/{paper_id}` | 单论文，fields 参数裁剪返回字段 |
| `GET /paper/{paper_id}/references` | 出边（该论文引了谁），每条边可带 contexts/intents/isInfluential |
| `GET /paper/{paper_id}/citations` | 入边（谁引了它），同上 |
| `GET /paper/{paper_id}/authors` | 作者分页 |
| `POST /paper/batch` | 批量取论文（文档称上限 500 IDs/次——未实测成功，见限流节） |
| `GET /paper/search` | 相关度搜索，offset/limit 分页（limit≤100） |
| `GET /paper/search/bulk` | 批量导出搜索，token 游标翻页，可 sort=citationCount:desc |
| `GET /paper/search/match` | 标题精确匹配，返回 matchScore（实测） |
| `GET /paper/autocomplete` | 标题自动补全 |
| `GET /author/{id}` `/author/{id}/papers` `/author/batch` `/author/search` | 作者侧 |
| `GET /snippet/search` | 文本片段搜索 |

支持的 paper_id 体系（spec 原文）：S2 sha、CorpusId、DOI、ARXIV、MAG、ACL、PMID、PMCID、URL（可识别 semanticscholar/arxiv/aclweb/acm/biorxiv 域名 URL）。

### 实测记录（2026-09-19，全部无鉴权）

| 探测 | 结果 |
| --- | --- |
| `GET /paper/arXiv:1706.03762` | 200，0.53s。返回 sha+CorpusId+MAG+ArXiv 完整 externalIds；referenceCount=41，citationCount=193096，influentialCitationCount=20746 |
| `GET /paper/ARXIV:hep-th/9901001` 与 `ARXIV:astro-ph/0001258` | **200——老格式 arXiv ID 正常解析**，且附 MAG/DOI 交叉 ID |
| `GET /paper/ARXIV:2609.10001`（publicationDate 2026-09-09） | 200——**新论文收录延迟 ≤10 天** |
| `GET /paper/{id}/references?fields=contexts,intents,isInfluential` | 200：每条边带 `contexts[]`（引用处原文句子，单条边可多 context）、`intents[]`（取值实测 `background`/`methodology`/`result`）、`isInfluential` 布尔 |
| `GET /paper/{id}/citations?fields=...` | 200：结构同 references（`citingPaper` 嵌套）；**2026 年新引文 contexts 全空**——contexts 依赖施引论文全文已处理，新入库边只有裸边无上下文 |
| `GET /paper/search/bulk?query=transformer&sort=citationCount:desc` | 200：total=382,560，token 游标翻页，排序生效 |
| `GET /paper/search/match?query=attention is all you need` | 200：命中 transformer 论文，matchScore=133.37 |
| `GET /paper/{id}?fields=embedding.specter_v2` | **200：直接返回 768 维 SPECTER2 向量**（`{model:"specter_v2", vector:[...]}`）——单篇 embedding 白嫖通道实测可用 |
| `POST /paper/batch`（4 个混合 ID） | **始终 429**（十余次尝试跨 ~30 分钟未成功一次），POST 类端点在匿名池里被掐得最狠 |

### 引用边属性模型

边本身是一等对象（swagger `Citation`/`Reference` 定义）：`contexts`（施引论文正文中提及该引用的句子数组）、`intents`（三分类：background/methodology/result——与 FAQ 的 Background/Method/Result Extension 对应[^s2faq]）、`contextsWithIntent`、`isInfluential`。

- **isInfluential**：由「Identifying Meaningful Citations」（Valenzuela, Ha, Etzioni，AAAI 2015 Workshop）定义的监督分类器生成——特征含引用计数与引用上下文，论文报告 precision 65% @ recall 90%；FAQ 明示依赖施引论文全文可得性，覆盖不全[^valenzuela15][^s2faq]。
- **intents**：模型出自 Cohan et al. NAACL 2019「Structural Scaffolds for Citation Intent Classification」，三分类[^cohan19]；同样受全文可得性限制（实测 2026 年新引文无 intents/contexts）。

## 二、Recommendations API：`api.semanticscholar.org/recommendations/v1`

Swagger：`/recommendations/v1/swagger.json`。仅两个端点：

| 端点 | 参数 | 实测 |
| --- | --- | --- |
| `GET /papers/forpaper/{paper_id}` | `from=recent`（默认）或 `all-cs`；`limit≤500`；`fields` | `from=recent` 对 2017 年 transformer 论文**返回空数组**——recent 池只含近 ~3 个月新论文；`from=all-cs` 返回 15 条（实测），主题为 Transformer 变体/注意力 NMT，citationCount 普遍很低（0-1047），含一条残篇式记录，整体像 embedding 近邻而非引用图近邻 |
| `POST /papers/` | body `{positivePaperIds:[], negativePaperIds:[]}` | 实测返回 10 条 2026 年新论文（TANGO、ZetaGPT、Multi-Head Attention Residuals 等），被引≈0——multi-seed 推荐默认也是 recent 池，定位是「新论文追踪」而非「经典相关工作」 |

**算法机制**（官方表述）：「state-of-the-art paper embedding model trained using contrastive learning」[^s2faq]——即 SPECTER 谱系。S2 官方博客明确 SPECTER 支撑 research feeds、作者消歧、论文聚类等多条产品线；SPECTER2 的训练信号直接是引用边——triplet（Q, P+, P-）中 P+ 取「被 Q 引用或引用 Q」的论文，P- 取随机（easy）或二跳引用（hard negative）[^specter2blog]。**也就是说 S2 的推荐是「引用图当监督信号训练 embedding → embedding 近邻当推荐」，不是实时图遍历。**

产品化形态：Research Feeds 以用户 Library 文件夹为正例、「not relevant」标记为负例，每日刷新，池子=近 3 个月新论文；前端实际调 `/api/1/library/folders/recommendations?folderIds=...&windowUTC=...`（需登录态，windowUTC 游标翻页）[^feedmd]。

## 三、Datasets API：`api.semanticscholar.org/datasets/v1`

- `GET /release/latest` —— **无需 key**（实测 200）：返回 release_id（实测 `2026-09-17`，约两天一更）+ 全数据集清单含描述与规模。
- `GET /release/{id}/dataset/{name}` —— **需 API key**（实测 401 `A valid API key is required`）：返回签名下载 URL。
- `GET /diffs/{start}/to/{end|latest}/{dataset}` —— 需 key：增量更新包，官方支持「下载一次全量 + diff 追平」模式[^s2docs]。
- **免费样本无需 key**：`s3-us-west-2.amazonaws.com/ai2-s2ag/samples/`（MANIFEST.txt 实测可拉，含每个数据集的 sample.jsonl.gz + README + s2ag.py 下载器）——schema 验证、管线开发不用申请 key。

### 实测 schema（免费样本逐字节验证）

- **citations**：`{citationid, citingcorpusid, citedcorpusid, isinfluential, contexts[], intents[]}`。注意三点：`citedcorpusid` **可为 null**（施引了语料外的文献——边指向语料外的黑洞）；`contexts` 是原文片段可能混入参考文献列表块（样本里看到整段 bibliography 文本）；`intents` 与 contexts 平行数组、元素为 null 或 intent 列表。
- **papers**：`{corpusid, externalids{MAG,CorpusId,ACL,PubMed,DOI,PubMedCentral,DBLP,ArXiv——全可空}, url, title, authors[{authorId,name}], venue, publicationvenueid, year, referencecount, citationcount, influentialcitationcount, isopenaccess, s2fieldsofstudy[{category,source:s2-fos-model|external}], publicationtypes, publicationdate, journal}`。**papers 里没有引用边**——边在 citations 数据集以 corpusid 关联，sha 体系经 paper-ids 桥接。
- **s2orc_v2**：README 描述含逐句/段落结构与 bibliographic references（S2ORC 是 S2 全文解析管线产物，Lo et al. ACL 2020[^s2orc]）。

## 四、限流与鉴权（实测 + 官方文档）

| 层级 | 文档口径 | 实测体感 |
| --- | --- | --- |
| 匿名 | 「1000 req/s **shared among all unauthenticated users**」，高峰期进一步 throttle[^s2api] | 全局共享池——**实测 ~45 分钟内 429 命中率 >80%**，GET 偶发穿透，POST /batch 零穿透。匿名配额基本不可做生产依赖 |
| API key | 入门档 **1 RPS 全端点**；邮件发表格申请（/product/api#api-key-form），私钥经邮件下发；部分端点（datasets 下载、diffs）**强制 key** | 401 实测 |
| Datasets 元数据 | /release/latest 无需 key | 实测 200 |
| Sample 数据 | ai2-s2ag S3 bucket | 实测无需 key 可下 |

服务状态页：`status.api.semanticscholar.org`。

## 五、引用图构建管线的公开描述

S2 的文献图构建方法发表于 Ammar et al. NAACL 2018「Construction of the Literature Graph in Semantic Scholar」[^litgraph]：PDF→GROBID 系解析→参考文献抽取→实体链接消歧→图构建；平台层论文为 Kinney et al. 2023「The Semantic Scholar Open Data Platform」（arXiv:2301.10140）[^s2ag]。

## 对自建完整形态发现层的启示

1. **citations 数据集是绕不开的地基**：2.4B 条带 influential/intent/contexts 属性的边、ODC-BY、月度 release + diffs 增量——自下载建图的原料里它的属性维度独一份（OpenAlex 只有裸边）。需要权衡：corpusid 键要经 paper-ids 桥到外部 ID；~255GB 下载 + 边表服务需要一次 API key 申请（免费）。
2. **embeddings-specter_v2（120M×768 维，Apache 2.0）直接消灭了「相似论文 embedding」这个子系统的训练成本**——下载 + ANN 索引（FAISS/hnswlib）即得 S2 同款推荐底座；单篇兜底还有 `fields=embedding.specter_v2` 白嫖通道（1 RPS key 后可用）。
3. **contexts/intents 展示了「边属性」的产品价值上限**（scite 同赛道）：texlate 的 LaTeX 源侧可自抽等效物（`\cite` 上下文 + 章节位置），且不受 S2 全文可得性限制——这是差异化空间。
4. **不要骑匿名 API**：共享池实测不可依赖；若走「API 兜底长尾」混合路线必须申请 key（1 RPS 决定了只能做 cache miss 兜底，不能做全图构建）。
5. **recent/all-cs 双池设计可抄**：新论文追踪与全库相似是两种产品语义，分开服务。
