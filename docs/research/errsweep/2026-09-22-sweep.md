## 2. 逐签名处置明细

### 2.1 L0 校验器名单块误杀 —— same_source 回显 + 长度比上界双闸（本 sweep 唯一根修）

- **签名面**：web 臂 `chunks.status=failed error_code=validate` 全档 7 格 / 3 任务，**单一签名族**：
    - `t_25e3f4d173b4db4a`（2609.17895v1 TabPFN-3.5，09-21 新案）seq 67/69/73/75/77 五连格——`A_contributors.tex` 贡献者名单段；
    - `t_4000988e3e67e27f` + `t_dd21359da49dea93`（同稿 2609.19969 两跑）seq 234/232——est=629 超大贡献者名单。
- **机理**（`chunks.warnings` 三行阶梯轨迹完整在档）：
    1. 模型产出**音译 + 原文括号注释**形（`本杰明·耶格尔（Benjamin Jäger）、…`）→ `_check_length` token 代理比 3.04-3.32 超出 `[0.3,3.0]` 上界 → whole×2 拒收；
    2. 阶梯 slots 臂回落 verbatim 名单（名单留拉丁原名本是正确态）→ `_check_same_source` 判「整段原文回显」拒收；
    3. 阶梯尽 → `fallback_orig` + `chunks_failed` 警告 → task 判 partial（zh.pdf 其实零编译错）。
- **根因**：`residual_en` 检查的人名豁免（`_keep_verbatim_run`：≥3 词且 ≥70% 首字母大写/地址覆盖）只在 run 级存在；`same_source`/`length` 两闸无同签名段级豁免——校验器对「src 本身是名单」这一内容类无建模。
- **修复**（commit `a54d9ac9`，最小面）：
    - `textutil/nets.py` 新增公共判据 `name_list_prose(s)`（`_keep_verbatim_run` 段级化，同口径零新逻辑）；
    - `validate/l0.py`：`_check_same_source` 豁免加 `name_list_prose(prose_src)`（须用未小写视图——大写占比是判据本体）；`_check_length` 上界 `TOKEN_RATIO_HI_NAMELIST=4.00` 仅名单 src 生效（下界不动——名单译空/截断仍拒收；>4x 膨胀仍拒收）；
    - `textutil/__init__.py` 导出；`docs/spec/validate.md` 规则表 + l0 模块 docstring 同步口径；
    - `tests/test_fuzz_validate.py` 双 oracle（`_o_same_source_hit`/`_o_length_sigs`）镜像同豁免——契约面不漂移。
- **边界论证**：普通散文首字母大写占比 ~10-15% 远低于 70% 阈（`Prof. Smith reported that...` 实测 2/14）；verbatim 名单 zh 零 CJK 本就不在 `residual_en` 判定范围；注释形 zh 的 `（Name）` run 逐段 `_keep_verbatim_run` 豁免不级联。
- **残余风险**：`et al.` 尾（`Shanghao Lu et al.` 50% cap）不达阈仍被拒——名单 + 连接词混合形保守不豁免（无实证个案，watch）；批级 `cjk_ratio` 文档闸不受影响（名单段对全文 CJK 占比影响可忽略）。
