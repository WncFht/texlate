# Benchmark 语料构建方法学调研 —— 为我们的 ~1,200 篇 arXiv 抽样设计找引证

> 调研日期：2026-09-14。纯文献调研，供方法学引证。
> 设计对象：从 arXiv 月度 bulk tar（月=簇）两阶段抽样 —— 先选 ~30 个月簇、再簇内按特征分层配额 ~35 篇，总 n≈1,200（1,000 核心 + 200 补强）。
> 相关前置文件：`corpus-arxmliv-unarxive.md`（底材与授权解剖）、`corpus-labels.md`（分层键底材）、`licensing.md`（license 分布）、`parse-metrics-literature.md`（指标口径）。本文件只答"语料怎么选、n 怎么论证、怎么发布"三问。

## 0. 一句话结论（先给答案）

**学术界的惯例是"能全量就全量、不能全量就随机抽 n≈100–600 人工核验"，几乎没有论文给 n 写统计论证**；断言型评估（olmOCR-bench）走"按失败模式分桶×每桶配额"，画像/多样性评估（OmniDocBench、Image2Struct、DocGenome）走"大池→聚类/分层→均衡配额"——**我们的两阶段月簇 + 特征配额与 OmniDocBench 同构、n 与 Image2Struct 同量级（都 ~1,200），先例链完整**。n 的统计论证（Wilson/rule-of-three/deff）文献里无人做过，需自担——这本身就是可引用的空白发现。

## 3. 数据集论文写作惯例（Line C：授权与钉版）

### 3.1「发清单不发内容」先例（manifest/pointer-only distribution）

| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **LAION-5B**（Schuhmann et al., NeurIPS 2022 D&B, arXiv 2210.08402）                                                                                                                                                            | 只发 parquet 元数据（URL+CLIP 分+flag），图片由用户用 `img2dataset` 自取——"URLs not images"，承袭 YFCC100M/CC3M/CC12M 谱系                                                                                                                  | 对我们："发 arXiv ID 清单 + 重建脚本，让用户从 arXiv bulk 自取"有直接先例                                                                |
| **Tweet-ID hydration**（Chen, Lerman & Ferrara, JMIR 2020, COVID-19 数据集；Sentiment140 更早）                                                                                                                                 | ToS 禁发原文 → 只发 tweet ID，用户 twarc 水合；附带"删除即自动失效"的合规红利                                                                                                                                                               | 同构先例：ID 清单是合规分发形态；注意其教训——**上游 API 断供后语料不可重建**（arXiv bulk 是 S3 requester-pays 静态 tar，断供风险低得多） |
| **unarXive 2022 open subset**（Saier, Krause & Färber, "unarXive 2022: All arXiv Publications Pre-Processed for NLP", JCDL 2023, arXiv 2303.14957, DOI 10.1109/JCDL57899.2023.00020；Zenodo 7752615 open / 7752754 restricted） | 论文原文："we share our dataset in two versions. (2) The full dataset ... is accessible through Zenodo's 'restricted access'" | **"按 license 切两版发行"在 arXiv 生态有逐字先例**；2024 版整集转 CC-BY-4.0 open                                                         |

### 3.2 钉版（reproducible pinning）惯例

- **版本化 DOI**：Zenodo record 逐版 DOI（unarXive 3385851→4313164→7752754→17431595 即此机制）；S2ORC 按 release 版本发行。→ 我们的 manifest 钉到具体版本号（arXiv ID + version 号）+ 语料自身版本 DOI。
- **per-item content hash**：unarXive JSONL 每行带 `_source_hash` 字段（源码 tar 的 hash）——**arXiv 生态里"清单+hash"钉版有直接先例**；scholarweave 的 manifest.xml 带逐分片 MD5+ID 区间（corpus-arxmliv §4）。
- **arXiv 版本即不可变单元**：arXiv ID+vN 内容冻结（license 按版本授予且不可撤销，licensing.md §1.1）——`(id, version, sha256)` 三元组即可完全钉死输入。
- **Datasheets for Datasets**（Gebru et al., CACM 2021;64(12):86–92, arXiv 1803.09010）：数据集发布文档模板（动机/构成/采集过程含**抽样方式**一节/预处理/用途/分发/维护）——我们写语料文档时的结构模板，"Collection Process" 节正是放两阶段抽样描述的位置。
- **Data Provenance Initiative**（Longpre et al., NeurIPS 2023 D&B, arXiv 2310.16787）：审计 ~1,800 文本数据集，发现大量 license 缺失/标错/收紧 → 支撑"逐篇记 license 字段"的惯例论证（与我们 licensing.md 的分布统计互相印证）；后续 "Consent in Crisis"（arXiv 2407.14933）记录网页数据授权收紧趋势。

### 3.3 可再分发子集圈定

- CC0+publicdomain+CC-BY(3.0/4.0)+CC-BY-SA ≈ **64.1 万篇**可公开发布源码；NC 系 +16.1 万（内部可用，公开发布存疑）——数字见 `corpus-labels.md`。
- 先例组合：unarXive（CC 子集单独 open 发布）+ LAION（pointer-only）+ scholarweave（镜像 ToU + 逐篇 license 字段）→ 我们的发布形态三选一：① CC 子集全文 + 非 CC 仅 ID；② 全量仅 ID manifest + 重建脚本；③ 全量 internal-only。

## 5. 风险与先例空白

1. **没有任何 benchmark 论文给 n 做统计功效论证**——SWE-bench n 是漏斗剩余、Nougat 连 n 都不报、olmOCR/OmniDocBench n 由"凑得动 + 均衡"决定、im2latex n=过滤剩余。我们若要写 n 论证，只能引统计文献（边际公式/rule-of-three）+ Card et al. 2020（EMNLP）作"应该论证"的方法学背书——**这本身是空白点，写得好反而是卖点**。
2. **"月=簇"的两阶段抽样无完全同构先例**，但三段先例可拼：OmniDocBench 的"大池→聚类→均衡"两阶段（视觉簇，非时间簇）；Image2Struct 的"每时间桶配额上限"（40/天）；arXiv bulk 的 yymm 物理分块。**措辞建议**：写成"two-stage cluster sampling with months as PSUs (primary sampling units)，配额按特征分层"——术语对齐抽样文献（PSU/SSU），不要自创名词。
3. **ρ（月间 ICC）无文献值**：deff 论证需要 ρ 估计——TeX 特性（docclass 年代、包流行度）存在月间漂移相关，但量未知。**行动项：用 corpus_v2（139 篇跨 1996–2026 多月）估几个关键特征的 ρ 上界**，哪怕粗糙（如 docclass=revtex 的月间方差分量）也足以论证"m 小优于簇大"。注意 EPI 30×7 的 m 比我们 35 小——若 ρ 不可忽略，30×35 的 deff 惩罚比 EPI 重。
4. **事后分层在 NLP benchmark 里几乎无人做**：olmOCR 用 macro-avg（等权桶）、DocGenome 用"eval 与全集同分布"（比例分配规避了加权）——两种口径都报（per-stratum 率 + 加权池化率），避免被审"加权益处不明"。
5. **补强桶（200 篇）不可入池化估计**——olmOCR 惯例是对抗桶单列 macro-avg 不混入主分布；报告须明示核心 1,000（概率样本，可加权泛化）与补强 200（非概率，只报桶内率）的估计语义差。olmOCR 另有一条值得抄的公平性声明："bench built after the model, to prevent unfairly iterating on the benchmark"。
6. **license 逐篇判定是抽样前必做项**：配额若先抽后判 license，non-exclusive 占 ~46–60%（licensing.md）会吃掉近半配额；先例做法（unarXive）是**先按 license 切层再抽**——分层键含 license 不只是法务需要，也是抽样效率需要。
7. **去污染声明是新基准论文标配**：olmOCR URL 级 dedup vs 训练集、OCRBench v2 私有 held-out 集、GOT-OCR 文本相似度过滤、Image2Struct 窗口后置采集。我们语料对应物：**training-cutoff 后窗 / 与 fixture 的 hash 去重 / 明说语料未进任何模型训练集**。
8. **数据集 license 全行业 sloppy**（多数"未声明"），但点名声明者给了模板：olmOCR ODC-BY-1.0、DocGenome CC-BY-4.0、OmniDocBench "research only"、TeXpert MIT——我们若明示 (id,version,hash) manifest + CC 子集正文，即优于领域默认水位。
