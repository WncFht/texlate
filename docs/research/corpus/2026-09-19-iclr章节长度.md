## 管线脚本（bench/py/）

- `iclr_map.py` — 三层映射：OpenReview 缓存自带 arxiv_id 直录 → OpenAlex `search=` 标题验证（exact/归一 fuzzy≥0.87）→ Semantic Scholar `/paper/search/match` 仲裁。`--phase oa|s2|all`，错误行非终态自动重入。
- `iclr_fetch.py` — 走 `texlate.arxiv.acquire_source`（HEAD+GET e-print+unpack+ 钉版缓存），串行 ~6s/篇，独立 ratelimit 账。
- `iclr_pdf.py` — OpenReview `/pdf?id=` 双代际下载（见坑①）。
- `iclr_sections.py` — LaTeX 臂切分：`\input` 递归展开 + .bbl 内联 + `\section` 边界 + detex 词数 + 17 桶归一。
- `iclr_pdf_sections.py` — PDF 臂切分：`pdftotext -layout` + 字距 despace + 编号单调/Title-Case/目录点线三闸门（见坑⑤）。
- `iclr_stats.py` — 双臂 join（每篇 LaTeX 优先 PDF 兜底）→ bucket×year 分布 + track 分层 + 双臂校准比。

## 已踩的坑

1. **OpenReview 双代际**：api2.openreview.net 只服务 v2 论文（约 ICLR 2024+），更早年份必须走 api.openreview.net。两站登录各发各的 token（`{"id":user,"password":pass}` → JWT），按年份路由首试、404 互兜底。匿名访问一律 ChallengeRequiredError，必须登录。
2. **OpenAlex API key 付费预算耗尽**：key 返回 `Insufficient budget ... resets at midnight UTC`，命中后本进程永久切匿名（mailto）通道；匿名池遇集群拥挤也间歇 429。
3. **S2 match 漏报 arXiv**：`/paper/search/match` 只回最佳单条实体，命中 OpenReview 记录时不报 arXiv 重复记录的 externalId——实测仲裁回收率仅 ~2%（5/300），`no_arxiv`/`s2_nomatch` 均不可信为终态，须待 OA 恢复后二刷。
4. **网络抖动**：本地代理周期性瞬断（ConnectError/TLS unexpected EOF），arxiv.org 曾整段 TLS 断连；直连出口整体不通，代理为唯一通路。所有抓取行均按非终态设计，断点重跑即可。
5. **ICLR PDF 字距大写标题**：早年版式标题字距拉开（`1   I NTRODUCTION`），raw 模式编号与标题分行、layout 模式合并但首字母常被拆成伪「附录字母 A」。解法：`-layout` + despace 正则 + `A+BSTRACT→ABSTRACT` 白名单拼回 + 附录字母编号必须在数字编号之后 + 标题含 `?`/`!` 拒收。实测 663/663 零失败。
6. **S2 pending 覆盖**：原设计只仲裁 oa_miss，已扩展为「无 arxiv_id 且非 S2 终态 + 从未尝试」全量，OA 全挂时 `--phase s2` 可独立扛全量。

## 备选数据集（已评估，未采用）

- **unarXive 2022**（TUD/Zenodo）[^unarxive]：全 arXiv ≤2022 的 LaTeX→XML 结构化数据，section 标签现成，天然覆盖 2017–2022 有 arXiv 的 ICLR 论文，也是最权威的切分对照基准；体积 ~60-80GB，2023+ 不覆盖。
- **S2ORC / peS2o**[^s2orc]：Grobid 解析全文，理论上能盖 OpenReview-only 论文；~150-200GB 分片，需按 S2 paperId join。
- Kaggle arXiv / S2AG / OpenAlex 仅元数据 + 摘要，无章节不可用。

结论：现有管线已跑通且零人工成本，换数据集不省总时间；unarXive 保留作切分质量对照候选。
