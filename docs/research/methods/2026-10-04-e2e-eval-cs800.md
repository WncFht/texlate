# e2e_eval_cs800 跨层新 CS 800 篇冻帧评测（2026-10-04）

> **结论**：800 篇跨层新 CS 冻帧全链路实测收官——zh 可交付 **725/800（90.6%）**，反超同帧 base 臂（89.4%）1.2 个百分点。首波（run-1）撞上上游 swe-2 约 11h 的 429 限流风暴（被拒 91,758 次），144 个 xlat 格烧穿重试预算，表面读数一度只有 74.3%；网关恢复后两波 regen 补跑（$25.84）回收 133 个翻译格，交付率回到真实水位。分层看：e-era 574 篇 **94.6%**、recent 各切片 70%~100%——均修复到贴平或超过各自 base 直编上限。fixloop 修复率 98.0%（195/199）不含 LLM 调用，与限流无关地在 800 篇尺度复现 CS-200 判决。**90.6% 是本帧能力读数；74.3% 是限流账，已被补跑证伪。**
> **状态**：时点证据（2026-10-04 收官口径，run-1+run-2+run-3 三波合并、dedup 逐格还原为所复用终态）
> **日期**：2026-10-04

## 1. 设计动机

CS-200 的 95.5% 是 200 篇样本读数，遗留「放大样本量是否保持」的开放问题。本 spec 为 `e2e_eval_cs` 的放大兄弟件（`e2e_eval_cs800`，同一条 route→xlat→compile→fixloop→base→layoutqc 六段链、同一个 eval 闸）：

- **帧**：跨层新 CS 并集（`e_2021_25|cs` ∪ recent-ish 的 cat_group=cs，五 manifest 去重 1,423 篇 ∩ 湖可供应格 940）分层等比抽 800（seed=20261003 → e-era 574 + recent-ish 226），落 `bench/nominations/e2e_eval_cs800.jsonl`，帧 sha `bafd9bb24333bc94`。
- **世代**：EPOCH `2026-10-cs` 与 CS-200 同代、共享 dedup 键域——两帧交叠的 164 篇在 fp 相同处直接借账，新 636 篇独立实测；两帧是同一代测量的两档样本量。

## 2. 终态账（三波合并、dedup 还原口径）

### 2.1 分 stage（对照 CS-200）

| stage    | CS-800 终态分布                                            | CS-200 终态分布                            |
| -------- | ---------------------------------------------------------- | ------------------------------------------ |
| route    | ok 748 / reject 52                                         | ok 199 / reject 1                          |
| xlat     | ok 666 / partial 63 / error 19 / skip 52                   | ok 175 / partial 17 / error 7 / skip 1     |
| compile  | clean 616 / partial 80 / fail 32 / skip 71 / fault 1       | clean 161 / partial 23 / fail 8 / skip 8   |
| fixloop  | clean 162 / partial 33 / error 16 / fail 4 / reject 585    | clean 43 / partial 7 / fail 1 / reject 149 |
| base     | clean 454 / partial 261 / error 48 / fail 33 / reject 4    | clean 113 / partial 79 / fail 7 / reject 1 |
| layoutqc | ok 505 / clean 223 / reject 72                             | ok 129 / clean 63 / reject 8               |

两帧账面不可直接对读的三处结构性差异：

- **route reject 52** 不是路由判定变严——48 格签名为 `lake cell unfetchable`（湖格供应失败，与 base error 48 同源同篇），3 格 `garbage`、1 格无签名。CS-200 池经过一次供应筛选，本帧 940 可供应格中仍有 48 格在实测时取不到件。
- **xlat skip 52 与 route reject 52 完全同篇**——逐 idc 核对一一对应，签名 `needs`，是路由死者的下游级联标注而非翻译失败；有机 xlat 死格只有 error 19。
- **fixloop error 16 / layoutqc reject 72** 同理为级联标注（`upstream:compile has no DONE row` / `qc_no_input`），修复环与质检自身无失败。fixloop reject 585 = `declined:not_wanted` 530 + `declined:route_dead` 52 + `declined:no_compile` 3。

### 2.2 逐篇交付账

| 终态                                        | 篇数 |
| ------------------------------------------- | ---: |
| compile clean（含 fixloop declined）        | 616  |
| compile partial                             | 80   |

| compile fail → fixloop unfixable            | 3    |

## 3. 429 限流事故账

run 窗口 2026-10-03 06:57 → 2026-10-04 07:59（25h）。网关逐请求账本（key `1edae453`）全窗：200 完成 9,870 次、**429 被拒 91,758 次**（被拒请求零 token 计费）、499 8 次。逐小时分布：

| 时段（run 相对时） | 状态                                            |
| ------------------ | ----------------------------------------------- |
| t+0~12h            | 健康：~590 完成/h，429 零星个位数               |
| t+13h（~19:57）    | 前兆：429 50 次 + 499 8 次                      |
| t+15~17h           | 第一波：429 每小时 2.5k→7.9k，完成数 202→164/h  |
| t+18~21h           | 全黑约 4h：429 每小时 13k~18.6k，完成合计 37 次 |
| t+22h              | 半恢复：187 完成 + 11.4k 拒发                   |
| t+23~25h           | 恢复：525→600 完成/h，排干余队收官              |

xlat error 的落账时间与此完全同相：前 12h 健康段仅 16 格 error（有机底噪 ~2.7%，与 CS-200 的 3.5% 同量级），t+15h~t+25h 限流段 128 格——重试预算（max_tries=5）在拒发窗口内耗尽即在飞格烧穿。按分层看，e-era xlat error 18/574（3.1%）仍是有机水位，dev_recent 77/111、holdout_recent 40/106、sw 9/9 才是风暴烧损。

**估算限流代价**：若按 e-era 的有机 error 率（~3%）折算全程，xlat error 应约 24 格，实际 144——风暴净烧 ~120 格，对应交付率 ~15 个百分点。修正规能力读数 ≈ (594+120)/800 ≈ 89%，与 e-era 实测 92.7% 互洽——补跑实测 90.6% 落地，估算口径被验证。

### 补跑回收账（run-2 / run-3）

网关恢复后两波补跑同帧重放（`--sel '*' --allow-regen --max-cost 80`，只重跑 retriable 格，终态格经 dedup 直接借账）：

| 波次  | 窗口              | 新跑格 | 表内计费 | 回收 xlat | 残余                    |
| ----- | ----------------- | -----: | -------: | --------: | ----------------------- |
| run-2 | 10-04 15:09→21:05 |    195 |   $22.64 |      128  | xlat error 24 / skip 52 |
| run-3 | 10-04 21:08→22:03 |     70 |    $3.20 |        5  | xlat error 19 / skip 52 |

补跑窗口网关账本：完成 2,525 次（输入 5.96M / 输出 1.69M / 缓存读 0.25M），429 仅 53 次零星。run-2 回收 128 格（ok 115 + partial 13），run-3 边际回收仅 5 格——残余 19 格 xlat error 为有机失败（签名 `xlat:fault=N`，N=1~7，块级校验/翻译异常耗尽重试），52 格 skip 全系 route 死者级联，**补跑到此收敛，第三波后不再放**。

两波各有一格收尾缺口：`2504.11492` 的 layoutqc 在 run-2/run-3 均 executor-error 未落账——但 `qc.json` 产物实际写出且校验通过（`qc_tier:clean`），是终态记录写入路径的确定性内核 bug，非质检失败；该格交付侧无影响（compile clean），按产物计入 QC 面。

## 4. fixloop 判决

真实修复尝试 **199 格**（compile clean 命中 _want_fix 90 + partial 77 + fail 32），救回 195（clean 162 / partial 33），**修复率 98.0%**——与 CS-200 的 98% 一致，在 199 次尝试尺度上第三次复现。decline 面 reject 585 = `not_wanted` 530（compile clean 免修）+ `route_dead` 52 + `no_compile` 3；error 16 全为 `upstream:compile has no DONE row` 级联标注。修复环不调用 LLM，全程不受限流影响。

## 5. 失败归因（有机部分）

- **compile fail 32**：undefined_cs 23（集中在 e-era——老论文宏定义病）、missing_file 5（lgrenc.def 2、acl.sty 2、sn-jnl.cls 1）、runaway_output 2、syntax 1、emergency 1。29/32 已被 fixloop 修回。
- **fixloop unfixable 4**：`dirty_pdf:sentry:page_flood`、`stuck:env_mismatch`、`acceptable_pdf`、`unfixable:syntax` 各 1——其中 1 格挂在 compile clean 上不影响交付，真损失交付的 3 格。
- **compile fault 1**：`upstream-lost`——翻译产物在编译上游丢失的孤儿格，fixloop 按拒收处理。
- **route reject 52**：`lake cell unfetchable` 48 + `garbage` 3 + 无签名 1——供应侧死格，与翻译链无关；其 xlat skip 52、compile skip 71 均为同源级联。
- **xlat error 19**：补跑后残余有机失败，签名 `xlat:fault=N`（N=1 居多 12 格，最高 fault=7）——块级校验失败或翻译异常耗尽重试的逐块死因，非风暴烧格。
- **base 臂 error 48 / fail 33**：error 48 全为 `lake cell unfetchable`（与 route 拒同源）；fail 33 以 undefined_cs 18 为主、e-era 集中——老论文缺件病的直编侧读数，与 compilecensus-5000 普查口径互证。

## 6. 付费账

xlat 唯一付费段。三波表内计费合计 **$123.24**（run-1 $97.40 + run-2 $22.64 + run-3 $3.20）。网关账本：run-1 全窗 9,870 次完成（输入 24.65M / 缓存读 0.67M / 输出 5.87M）+ 91,758 次 429 零计费；补跑窗 2,525 次完成（输入 5.96M / 缓存读 0.25M / 输出 1.69M）+ 53 次 429。按 729 篇翻译成功格均摊 ≈42k in / 10.4k out 每篇。

## 7. 口径注记

- 全部数字为逐 (idc,stage) 末态、dedup 行跨 run 还原为所复用终态的**三波合并口径**（run-1 全帧 + run-2/run-3 两波 regen 补跑）；CS-200 借账 164 篇按同口径计入分布。
- xlat error/skip 按 spec 属 retriable 而非终态——run-1 收官时 144+51 格中 133 格已被两波补跑回收；残余 19 格 error 是两波补跑后仍耗尽的有机失败，52 格 skip 与 route 死格逐篇对应为级联标注。
- fixloop reject 与 layoutqc reject 均为结构化 decline/级联标注，不计入失败分子；`2504.11492` 的 layoutqc 因 executor 级 bug 两波均未落账，按已验证的 `qc.json` 产物（clean）计入 QC 面，内核欠条见 §8。

## 8. 结论与欠条

- **能力判决**：新 CS 池 zh 交付 **90.6%**（725/800），反超 base 直编臂 89.4%；分层 e-era 94.6% / holdout 89.6% / dev_recent 70.3% / sw 100%，除 dev_recent（供应死格最重切片）外均贴平或超过 base。与 CS-200 的 95.5% 同格局——编译链近无损、残余缺口在供应侧与个别有机 xlat 失败。
- fixloop 修复率 98% 在 199 次尝试尺度第三次复现，普查判断成立。
- **欠条一**：52 格供应死格（`lake cell unfetchable` 48 + `garbage` 3 + 无签名 1）需湖侧补件才能进入测量面；dev_recent 切片因此带 ~25% 结构性死格。
- **欠条二**：19 格有机 xlat error（`xlat:fault=N`）为逐块死因，待 xlat 校验器/重试策略改进后再收——当前属可接受的 ~2.4% 损耗。
- **欠条三**：`2504.11492` 的 layoutqc 终态记录写入路径存在确定性 executor bug（产物 `qc.json` 写出且验证通过、账本行不落），已两波复现；需修内核记账路径，否则该格在每波 accounting 里都是永久缺口。
- **欠条四**：fixloop unfixable 3 格真损失（page_flood/env_mismatch/syntax）+ compile fault upstream-lost 1 格。
