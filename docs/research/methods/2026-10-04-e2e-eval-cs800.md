# e2e_eval_cs800 跨层新 CS 800 篇冻帧评测（2026-10-04）

> **结论**：800 篇跨层新 CS 冻帧全链路实测收官——zh 可交付 **594/800（74.3%）**，表面较 CS-200（95.5%）低 21 个百分点，但跌幅几乎全部是测量天气：run 后段上游 swe-2 持续 429 限流约 11h（含 ~4h 全拒发，全程被拒 91,758 次），xlat error 144 格中约 126 格为限流烧格。健康窗口内完成测量的 e-era 574 篇 zh 交付 **92.7%**，贴平同帧 base 臂 92.3%，与 CS-200 的判决一致；fixloop 修复率 98.3%（115/117）不含 LLM 调用，完全不受限流影响。**本帧能力读数约 92%，74.3% 是限流账而非质量账。**
> **状态**：时点证据（2026-10-04 收官口径，run-1 单波跑完 25h，dedup 逐格还原为所复用终态）
> **日期**：2026-10-04

## 1. 设计动机

CS-200 的 95.5% 是 200 篇样本读数，遗留「放大样本量是否保持」的开放问题。本 spec 为 `e2e_eval_cs` 的放大兄弟件（`e2e_eval_cs800`，同一条 route→xlat→compile→fixloop→base→layoutqc 六段链、同一个 eval 闸）：

- **帧**：跨层新 CS 并集（`e_2021_25|cs` ∪ recent-ish 的 cat_group=cs，五 manifest 去重 1,423 篇 ∩ 湖可供应格 940）分层等比抽 800（seed=20261003 → e-era 574 + recent-ish 226），落 `bench/nominations/e2e_eval_cs800.jsonl`，帧 sha `bafd9bb24333bc94`。
- **世代**：EPOCH `2026-10-cs` 与 CS-200 同代、共享 dedup 键域——两帧交叠的 164 篇在 fp 相同处直接借账，新 636 篇独立实测；两帧是同一代测量的两档样本量。

## 2. 终态账（dedup 还原口径）

| -------- | ----------------------------------------------------- | ------------------------------------------ |

两帧账面不可直接对读的三处结构性差异：

- **route reject 52** 不是路由判定变严——48 格签名为 `lake cell unfetchable`（湖格供应失败，与 base error 48 同源同篇），3 格 `garbage`、1 格无签名。CS-200 池经过一次供应筛选，本帧 940 可供应格中仍有 48 格在实测时取不到件。
- **fixloop error 145** 中 144 格签名为 `upstream:compile has no DONE row (last=skip)`——xlat 死格的级联标注，不是修复环自身失败；真修复异常仅 1 格（`exception`）。
- **layoutqc reject 204** 全为 `qc_no_input`——204 篇上游死者的下游级联，质检自身零失败。

调度顺序与风暴窗口叠加决定了分层面貌：e-era 段在网关健康的前 ~12h 跑完翻译，交付率贴平 base 臂（92.7% vs 92.3%）——与 CS-200「zh≈base」的判决同构；recent 各切片排在队列后段，翻译窗口恰好撞上限流期，dev_recent 111 篇中 105 篇上游死。base 臂不吃 LLM 调用，各分层读数正常（72%~92%），证明损伤集中在翻译段而非语料或编译。

## 3. 429 限流事故账

run 窗口 2026-10-03 06:57 → 2026-10-04 07:59（25h）。网关逐请求账本（key `1edae453`）全窗：200 完成 9,870 次、**429 被拒 91,758 次**（被拒请求零 token 计费）、499 8 次。逐小时分布：

| 时段（run 相对时） | 状态                                               |
| ------------------ | -------------------------------------------------- |
| t+0~12h            | 健康：~590 完成/h，429 零星个位数                   |
| t+13h（~19:57）    | 前兆：429 50 次 + 499 8 次                          |
| t+15~17h           | 第一波：429 每小时 2.5k→7.9k，完成数 202→164/h     |
| t+18~21h           | 全黑约 4h：429 每小时 13k~18.6k，完成合计 37 次     |
| t+22h              | 半恢复：187 完成 + 11.4k 拒发                       |
| t+23~25h           | 恢复：525→600 完成/h，排干余队收官                   |

xlat error 的落账时间与此完全同相：前 12h 健康段仅 16 格 error（有机底噪 ~2.7%，与 CS-200 的 3.5% 同量级），t+15h~t+25h 限流段 128 格——重试预算（max_tries=5）在拒发窗口内耗尽即在飞格烧穿。按分层看，e-era xlat error 18/574（3.1%）仍是有机水位，dev_recent 77/111、holdout_recent 40/106、sw 9/9 才是风暴烧损。

**估算限流代价**：若按 e-era 的有机 error 率（~3%）折算全程，xlat error 应约 24 格，实际 144——风暴净烧 ~120 格，对应交付率 ~15 个百分点。修正规能力读数 ≈ (594+120)/800 ≈ 89%，与 e-era 实测 92.7% 互洽。

## 4. fixloop 判决

真实修复尝试 118 格（compile clean 命中 _want_fix 23 + partial 69 + fail 26；另有 1 格 exception 异常），救回 115（clean 92 / partial 23），**修复率 97.5%**（含异常格）/ **98.3%**（不含）——与 CS-200 的 98% 一致。decline 面 reject 538 = not_wanted 477（compile clean）+ 上游死级联 60 + compile partial 1。修复环不调用 LLM，风暴对其零影响。

## 5. 失败归因（有机部分）

- **compile fail 26**：undefined_cs 19（全在 e-era——老论文宏定义病）、runaway_output 2、missing_file 4（lgrenc.def 2、acl.sty 2）、emergency 1。24/26 已被 fixloop 修回，仅剩 §6 欠条的两格。
- **fixloop unfixable 2**：`dirty_pdf:sentry:page_flood` 1（CS-200 同款唯一修不了类）+ `stuck:env_mismatch` 1。
- **route reject 52**：`lake cell unfetchable` 48 + `garbage` 3 + 无签名 1——供应侧死格，与翻译链无关。
- **xlat reject 9**：`regen_gate` 闸拒——评测冻帧下禁止重生的格，结构性 decline。
- **base 臂 error 48 / fail 33**：error 48 全为 `lake cell unfetchable`（与 route 拒同源）；fail 33 以 undefined_cs 18 为主、e-era 集中——老论文缺件病的直编侧读数，与 compilecensus-5000 普查口径互证。

## 6. 付费账

xlat 唯一付费段。run 收官表内计费 **$97.40**；网关账本全窗 9,870 次完成调用：输入 24.65M tok（缓存读 0.67M），输出 5.87M tok。按 596 篇翻译成功格均摊 ≈41k in / 9.8k out 每篇，低于 CS-200 的 47k/12k——限流截断了部分格的重试里程。91,758 次 429 拒发零 token 计费，代价全部是时间（run 拉长 ~11h）。

## 7. 口径注记

- 全部数字为逐 (idc,stage) 末态、dedup 行跨 run 还原为所复用终态的合并口径；CS-200 借账 164 篇按该口径计入分布。
- xlat error/skip 按 spec 属 retriable 而非终态——本账按 run 收官末态计入「上游死」，其中 ~126 格是限流烧穿的重试耗尽格，上游恢复后 regen 重跑可全部回收。
- fixloop reject 与 layoutqc reject 均为结构化 decline/级联标注，不计入失败分子。

## 8. 结论外推与欠条

- **能力判决**：新 CS 池 zh 交付能力 ~92%（e-era 实测 92.7%、修正规 ~89%），与 CS-200 的 95.5% 同格局——编译链无损、瓶颈在翻译侧死格。74.3% 的头读数是上游限流账，不应外推。
- fixloop 修复率 98% 在 800 篇尺度复现，普查判断成立。
- **欠条一**：~152 格 xlat 死格（144 error + 8 regen_gate 外 skip 级联不计）待网关健康窗口 regen 重跑回收——预计全帧交付率回升至 ~92%，届时本账应重切。dev_recent/holdout_recent/sw 切片的当前读数是风暴产物，不作分层结论。
- **欠条二**：48 格 `lake cell unfetchable` 供应死格与 CS-200 同型，需湖侧补件才能进入测量面。
