# 重试案重建 + values 截断质量实验 + keep-roster 应力测试（2026-09-29）

> **结论**：夜跑 v5 的「+34% 调用数」已归因为 **~50 个 ph 密集 member 的梯级重试风暴**（136 次降级调用，人均重试 2.7 次、单 member 最多 15 次），与批量解析失败、锚点校验严宽无关；今天在健康上游上重放同一批 member，v5/v6 各臂全部不再失败，唯一存活残留是 NBSP 丢弃类（对一切 keep 变体免疫）。values 上下文截断的质量代价经 XCOMET-QE 实测为 **零**（2k 截断 vs 全量 vs 全无，配对 Δ 95%CI ±0.005，全在噪声内）——但 v6 原案的「段内 values 行」竟比全量 values 尾块还贵（+100% vs +88%），精简版 keep-only 只需 +23%。

## 1. 问题与实验矩阵

基线报告 §4.2 留了两个开口：v5 调用数膨胀（393 vs v4 的 294）的归因未核实；以及拟议的 v6（段前 `keep:` 点名 + 段内 `values:` 行）能否降重试、values 截断会不会伤质量。本文三个实验：

| 实验         | 方法                                                  | 回答                                    |
| ------------ | ----------------------------------------------------- | --------------------------------------- |
| 重试案重建   | 网关账本逐请求 → argmin 尺寸匹配 → member 归因        | 夜跑到底是谁在重试、重试几次            |
| 真实案例重放 | 捞出的批原样重发，v5/v5fv/v5nv/v6/v6b/v6c 六臂 ×3 rep | 现在的 prompt 下重试率怎么变            |
| values 质量  | XCOMET-XL QE 给四臂译文打分（309 个 unit 配对）       | 截断/全量/删 values 各值多少质量        |
| 温度应力     | 同批 temp=1.0 重放 v5/v6 ×3 rep                       | keep 点名在高压下是否真降错（机制探针） |

素材：v5 夜跑臂 9 篇（key `268cd3…`，`swe-2-medium` 窗口逐篇对齐 task_usage）；重放靶 = 2609.19506 para 层 44 批中历史降级最多的 8 批（{2,9,12,13,17,27,36,39}，覆盖该篇 76 次 para 降级调用的 97%）。

## 2. 夜跑重试案重建：~50 个 member 在烧 136 次调用

归因法：texlate 载荷确定性可重算——对每个候选调用（批载荷 / 单 member 载荷 / 结构单发）预测 `system_chars+user_chars`，在批调用上校准 tok/char 比（~0.31–0.33），全候选 argmin 匹配（批 err<15%、member err<12% 判信）。脚本 `tmp/forensic_calls.py`，产物 `tmp/forensic_v5_<paper>.json`。

| 论文       | 降级调用 | 去重 member |     | 论文       | 降级调用 | 去重 member |
| ---------- | -------: | ----------: | --- | ---------- | -------: | ----------: |
| 2609.19506 |       80 |          17 |     | 2609.20610 |        7 |           6 |
| 2609.20533 |       18 |           7 |     | 2609.20739 |        6 |           6 |
| 2609.20581 |       14 |           4 |     | 2609.19844 |        5 |           4 |
| 2609.19929 |        5 |           5 |     | 2609.19990 |        1 |           1 |
| 2609.20523 |        0 |           0 |     | **合计**   |  **136** |      **50** |

- **形态**：不是「~72 个一次性退单」，是少数顽固 member 反复撞梯级——19506 的 17 个 member 分摊 80 次调用，次数分布 [15,11,10,9,7,6,5,3,3,2,2,2,1,1,1,1,1]，榜首一个 member 独烧 15 次（撞满梯级上限后仍降级）。
- **画像**：降级 member 的 ph 密度 mean=27.7 / median=28.5 / max=59，语料基线 mean≈10.4、p95≈24——**ph 密集段是重试源**。kind 分布 para 111 / caption 18 / section_title 7。
- **NBSP 不是夜跑驱动**：136 次归因 member 中 74 个源文 NBSP=0（nbsp mean=0.69）——夜跑失败模式是 ph 枚举量级溢出，不是空白符盲。
- **对 §4.2 的修正**：膨胀不是「批量 `[n]` 协议解析失败整批退单翻」（解析失败的签名是 PARSE-FAIL 后整批 member 级重发，归因里看到的却是**同 member 反复**），而是上游退化期 ph 密集 member 审计不过、梯级逐层重试。v4 臂归因不可恢复（恒等表把每次调用灌到 ~120k tok，member 尺寸信号被淹 + 同 key 有外来流量），但 v5 侧证据链已闭合。

## 3. 真实案例重放（健康上游，temp=0.2）

8 个靶批 × 3 rep = 24 调用/臂：

| 臂                             | 成员级失败 | 明细                                                        |
| ------------------------------ | ---------- | ----------------------------------------------------------- |
| v5（2k values 尾块，现产形态） | 0/24 调用  | —                                                           |
| v5fv（values 不截断）          | 0/24       | —                                                           |
| v5nv（无 values）              | 3 member   | batch36 m0/m11/m12，全 `[[NBSP]](in=k,out=0)`               |
| v6（keep+values 段内）         | 3 member   | 同批同 member（r0: m11,m12；r2: m0），全 NBSP               |
| v6b（keep 只列 `[[X_n]]`）     | 9 member   | batch36×6 + batch03r2 五连喷（m1/m10/m11/m14/m15），全 NBSP |
| v6c（keep 带 `×n` 计数）       | 3 member   | 同 NBSP 类                                                  |

- 历史败过的 member 今天在各臂**零复发**——夜跑风暴需要上游真实退化才复现，健康期测不出重试率差。
- 唯一存活失败类是 **NBSP 丢弃**：批内多点同时掉 `~`（batch03r2 五 member 齐掉），与 keep 有无、keep 形态（全列/计数/只列编号 id）、values 有无全部无关——上游批次级情绪，非 prompt 可治。
- 处理方向只剩审计侧：`_BENIGN_EXTRA_TYPES={"NBSP"}`（retry.py:328）已豁免「多译出」方向，「少译出」方向仍硬败——把 NBSP missing 降级为 warn 即可消掉该类全部残留（每条都是「丢了排版软空格」级别的良性错）。

## 4. values 截断的质量代价：QE 实测为零

四臂译文（同一批源文同日重放产物）过 XCOMET-XL QE（内网 GPU 机，1218 对，src/mt 双侧 ph 还原成 fragment 后打分）：

| 臂                   |   n | mean QE | median | 配对 Δ vs v5（95%CI） | 胜/负（±0.01 阈值） |
| -------------------- | --: | ------: | -----: | --------------------- | ------------------- |
| v5（2k 截断 values） | 309 |  0.2592 | 0.2097 | —                     | —                   |
| v5fv（values 全量）  | 300 |  0.2540 | 0.2070 | −0.0041 ± 0.0057      | 77 / 85             |
| v5nv（无 values）    | 300 |  0.2548 | 0.2064 | −0.0032 ± 0.0060      | 92 / 80             |
| v6（keep+values）    | 309 |  0.2581 | 0.2061 | −0.0011 ± 0.0049      | 89 / 77             |

- **截断无害、全量无益、删除无损**：三点 Δ 全部落在 ±0.005 的噪声半宽内（配对 stdev≈0.05，可分辨下限 ~0.01，即 <4% of mean）。且方向非单调（无 values 和全量 values 都略低于 2k）——典型零效应签名。
- 限定 ph-bearing member（302/309）结论不变。
- 注意测量口径：这些 member 正是夜跑降级最狠的 ph 密集段——若 values 有帮助，这里该最显眼；QE 双侧还原了 fragment，故测的是「行文正确性」而非「ph 字面保真」（后者由审计另管）。

## 5. 成本重算：v6 原案其实比全量 values 还贵

19506 para 层实测 Σuser 字符（44 批 726 member，ph 最重篇=上界情形）：

| 形态                         |    Σuser |       Δ vs 裸载荷 | 备注                              |
| ---------------------------- | -------: | ----------------: | --------------------------------- |
| v5nv 裸 `[n]` 载荷           | 471,513c |                 — |                                   |
| v5 现产（+2k values 尾块）   | 559,601c |      +88k（+19%） | 全量表 361k 的 ~24% 被 2k 帽裁入  |
| **v6keep（keep 行 only）**   | 581,301c | **+110k（+23%）** | 每 member 一行点名，~36k tok      |
| v5fv（values 全量尾块）      | 888,633c |     +417k（+88%） | per-batch 合并去重后              |
| v6 原案（keep+ 段内 values） | 943,189c |    +472k（+100%） | values 按 member 重复、无批内去重 |

QE 零效应 + 这个成本表 ⇒ values 行不值得任何形态保留为「每 member 一份」；要留就留现产的批尾 2k 帽块（最便宜、质量无差），要砍就整类砍掉。

## 6. 温度应力测试（temp=1.0，机制探针）

同 8 批 ×3 rep = 24 调用/臂，把 temp 从产线 0.2 提到 1.0 模拟退化上游：

| 臂  | PARSE-FAIL | member 失败 | 明细                                                              |
| --- | ---------: | ----------: | ----------------------------------------------------------------- |
| v5t |          0 |           1 | batch36r1 m0 `NBSP(1→0)`                                          |
| v6t |      **1** |           3 | batch02r1 m2 `NBSP(16→0)` 整段清零、batch36r1 m11/m12 `NBSP(2→0)` |

- **keep 点名在应力下没有显出可分辨收益**：两臂失败都还是纯 NBSP 类；member 计数 1 vs 3 是噪声量级。temp=1.0 本身不够「退化」——swe-2-medium 在高温下枚举 ph 依然稳，说明夜跑风暴要的是真上游降级（限流/容量），采样噪声模拟不出来。
- **v6t 出了本次实验唯一一次 PARSE-FAIL**（batch27r2）：输出在 [10] 段中段脱轨，重新起了一遍 `[2]`…`[10]` 裸编号——形貌酷似输入里 `[n] keep:` 段头被镜像成独立行。n=1、temp=1.0，不能定罪，但这是 v6 新增的格式面第一次露出「可被模型回声化」的缝——落地时值得在 parse 层加一道「裸编号行容错」或对 keep 行改注释式前缀（如 `# keep:`）降镜像率。
- 综合：keep 机制对症夜跑主类（ph 枚举溢出）的推断仍然成立，但本环境下**测不出正面收益**——健康上游 + 高温都只给「不回归 + NBSP 残留」。

## 7. 结论与建议

1. **§4.2 归因关闭**：v5 调用数 +34% = ~50 个 ph 密集 member（ph≈28 vs 语料 ≈10）的梯级重试风暴，集中于上游退化窗口；不是解析失败、不是名单行化的校验副作用。
2. **keep-roster 定位修正**：它对症的是「ph 枚举溢出」这一夜跑主类（结构上有道理），但健康上游与 temp=1.0 应力下都测不出收益（无败可降）；**它治不好 NBSP 类**——那是批级上游情绪，唯一出路是审计侧 missing-NBSP leniency。新风险点：v6t 出现首例段头镜像型 PARSE-FAIL（n=1，待观察）。
3. **values 上下文可整类删除**：QE 证明 0/2k/全量三档质量不可分辨。建议：v6 落地形态 = **keep 行 + 保留现产 2k 尾块**（保守）或 **keep 行 + 删 values**（最省；QE 支持）；**不要**段内 values 行（+100% 成本且无益）。
4. **诚实限制**：夜跑量级的重试率差不可按需复现——需要下一次上游退化窗口或真实 soak 才能给 v6 的降幅定量。当前证据上限 = 不回归 + 机制对症 + 一处待观察的格式面风险。

## 8. 落地形态（同日进 src，`xlat-prompt-v6`）

建议 #1–#3 同日全部落地，但线形与实验假设的「`[i] keep: ids` 独立行」有一处关键差异：

- **线形改单行内联**：`[i] keep: <ids> | <enc>`——名单与正文同行、`|` 分隔。两行式（`[i] keep: ids\nenc`）被 fuzz 抓掉：成员编码字面以 `[k]`/`@@` 起头时会落回行首，`_NUM_LINE_RX` 多重集直接炸（iter 41 实捕）。内联后 enc 永不在行首，协议形起头的成员天然免疫。
- **keep-echo 解析容错**（应 §6 的「格式面风险」）：`_KEEP_ECHO_RX` 剥段首名单回显（`|` 可有可无、可接换行）；`_KEEP_ONLY_RX` 判名单独占段 → 剥成 `""` → `all(out)` 让整批退单翻——名单与成员 ph 多重集天然同集，留非空段会骗过 `diff` 把 `keep: ids` 原文漏成译文（宁可烧调用不泄漏）。
- **NBSP missing leniency 落地**：`_BENIGN_MISS_TOKENS={NBSP}`——只赦免「少译出」方向（丢失排版软空格是良性伤、§3 实证对一切 keep 变体免疫）；「多译出」（锻造）方向对全部 token 族仍硬败。
- **容量记账**：`pack_batches(overheads=[...])` 逐项开销取代定值 8——`batch_member_overhead` = 编号 8c + keep 前缀实长（ph 最重成员 ~660c），否则批悄悄超 12k 硬顶。
- **values 处置**：保留现产批尾 2k 帽块（保守档）——QE 三档不可分辨，删留皆可，先不动。
- 测试侧：`test_fuzz_xlat_batch` 新增 echo-strip/audit/overhead 三组契约，mock 与 `zh_lines_reply` 伪件同步剥名单（真实模型不回显元数据，伪件回显=假退单翻）。
