## 1. 设计动机

holdout-200 通用帧分层均衡的副作用是新兴切片被摊薄：e_2021_25|cs 仅 14 篇，答不了「新 CS 论文表现如何」。本 spec 为 e2e_eval 兄弟件（`e2e_eval_cs`，同一条 route→xlat→compile→fixloop→base→layoutqc 六段链、同一个 eval 闸），差异只在帧与世代：

- **帧**：holdout 留出层中 `stratum_cell ∈ {e_2021_25|cs, holdout|recent}` 且 `cat_group=cs` 的池（341 篇 ∩ 湖可供应格 336），分层等比抽 200（seed=20261002 → e-era 127 + recent 73），落 `bench/nominations/e2e_eval_cs.jsonl`，帧 sha `de2d7e75b1c86b09`。
- **世代**：EPOCH `2026-10-cs` 与通用帧 `2026-10` 代互不命中——两帧有交叠篇目，dedup 不借账，本帧是独立测量届。

## 3. 失败归因

### 3.1 compile fail 8 篇：散件无集中签名

undefined_cs 3、missing_file 3（`acl.sty`×2、`latex/sec/0_abstract.tex` 项目内部缺件 1）、runaway_output 1、emergency 1。唯一重复件 acl.sty 是 ACL 旧版模板文件，量级两篇，够不上宏包病——与 compilecensus 5000 普查「CS 缺件率 4.7% 且全为单例散布」的口径互证。

### 3.2 fixloop unfixable 1 篇

2209.00042，`runaway_output` → `dirty_pdf:sentry:page_flood`——编译产出页数洪水被判脏页拒绝，修复环无对应路由，是唯一修不了格。

### 3.3 xlat error 7 篇：块故障耗尽重试

全部 `chunks_retriable`：2104.00048（fault=2）、2111.00254（fault=8）、2306.00088、2504.11492、2509.22973、2510.08185、2608.28170（fault=1~5）。重试预算内未收敛即记 error——这是通用帧「块故障死 6」的同款死因，在本帧占不可交付的 7/9，是提升新 CS 交付率的第一抓手。

### 3.4 base 臂 fail 7 + reject 1

散件：missing_file 2（acl.sty 同源）、undefined_cs 2、syntax 等；reject 1 为 route 拒格级联。base 无 error——通用帧的 18 格湖格 unfetchable 在本帧为零，新 CS 论文的湖供应面干净。

## 5. run-6 QC 反馈修复（2026-10-03 补记）

`_qc_wanted` 补票环实测一轮：run-5 质检账中「编译 clean 但 `layout:overfull`」且 fixloop 被判 decline 的 9 篇全部进修复环并落地 clean——判决构成 acceptable_pdf 5 / clean 3 / reject:psfrag_route 1。逐篇 compile log overfull 计数对账：合计 351→149（−58%），3 篇清零、4 篇削减、2 篇不变（2510.16001 / 2104.00219 两篇 122/177 高件，属规则未覆盖的宽幅溢出类）。QC 质检账本身不重测——`cell_fp` 只含 spec 全代码哈希 + fp_input + fp 参数，不追踪上游 splice 变更，layoutqc 格 dedup 复用旧判决；上表数字取自修复前后 compile log 直接计数，非 QC 签名。

顺带重试面：8 格 xlat 死格（7 error + 1 skip）重评估全部被闸拒收，判决不变，零付费消耗；2209.00042 page_flood 第二次 unfixable（二连败）。zh 交付率不变 191/200——9 篇本就是 clean 可交付件，修的是质量不是交付。

## 6. 口径注记

- 全部数字为逐 (idc,stage) 末态取新、dedup 行还原为所复用终态的合并口径；killed run-1 留下的 `lost` 墓碑格已由 run-5 regen 臂（`--sel '*' --allow-regen --max-cost 60 --yes`）全部重跑落地，不计入终态。

## 7. 结论外推与欠条

- 「新 CS 论文交付」判决：zh 交付率 95.5%，瓶颈从编译侧转移到翻译侧——编译链（xelatex + fixloop + vendor）对新 CS 已接近无损，剩余不可交付的 78%（7/9）压在 xlat 块故障重试收敛上。
- fixloop 修复率 98% 支撑普查判断：裸编缺的件修复链都能接住。
- 欠条一：xlat 块故障的 fault 是否可通过提高 max_tries 或降级块重放回收，未实测；7 格全回收则交付率上限 99%。
- 欠条二：帧内 200 篇均为 2021+ 且 cs 组，e-era 与 recent 两层未分开报数——若需近期（recent）切片的独立读数，可复用本帧按 stratum_cell 重切，无需重跑。
