## 0. 结论先行

**默认模型：`swe-2-medium`**——唯一 **100% 硬契约**（80/80:0 丢占位符、0 丢命令、0 validator 错误）、reasoning 开销全场最低（p50 仅 98 字符，是"思考地板"）、输出 token 最省（中位 134）、延迟 5.9s/段可接受、promo 到 **2026-10-16**。

备选链：`swe-2-high`（契约 99%，慢 70%）→ `glm-5-2`（窗口期快选，promo 09-16 到期，硬契约 91% 且有灾难性吞占位符史）→ `swe-1-7-medium`（最快 2.9s 但有丢命令史）。
禁用：`swe-1-7-medium` 的 BIBITEM 事故 + `swe-1-7` 的 reasoning 爆炸尾部（p95=22k 字符思考）使两者只能当对照。

## 2. 排序用的指标管线（按优先级）

### L1 硬契约率（一票否决级）

`hard_ok = 无丢占位符 ∧ 无造占位符 ∧ 无丢脆弱命令 ∧ validator 无 error`。
丢占位符 = splice 后内容静默消失（E10 实证 0 编译错误）；丢 `\` 类命令 = 可能熔成 `\和` 这种未定义 cs 直接编译炸。**这是排序的第一键**，差 5% 就是合格线内外之别。

### L2 软信号：占位符换序（ord）

严格序守恒（src/zh 占位符序列逐一相等）**对中文翻译过严**——实测 73 处违例几乎全是合法重构（`of X`→`X 的`、英语状语后置→中文前置），每个占位符照样 splice 回自己的片段。处理方式：降级为观察项，不计入硬失败；唯二真伤形态是"结构性占位符离开其文本位"（BIBITEM 掉到条目文本后）——本次未观察到。

### L3 延迟 p50/p95 与 reasoning 开销

p50 决定吞吐（一篇 ~146 chunk 串行 ≈ p50×146），p95 暴露尾部风险；`reasoning_content` 长度 = 白烧的 token 与延迟的直接来源。**swe-2-medium 的 rsn p50=98 字符是全场唯一"思考地板"**——别人都在想，它几乎不想却对。

### L4 token 经济

tok_out 中位数（reasoning 计入计费的直接代理）；tok_in 中位数反映网关注入开销的型号分档。

## 4. 失败现场分析

- **glm-5-2 唯二的灾难性失败**：`1111.4914#3` run1 **连吞 9 个 MATH + `(i)/(ii)` 引用**（译文出现空洞"是 的一个特例"）；`S1` 两轮都丢 `\` 控制空格。它 91% 的硬契约率在免费集里垫底，且失败模式最恶性（静默大段丢失）。
- **swe-2-max 的真伤**：`1207.7214#0` 把 `\` 控制空格与后随中文熔成 `\和`/`\道`（未定义 cs，编译必炸）——更深的思考（rsn 600）反而产出更"中文"的句式、撞上更恶性的错误。思考深度≠契约收益。
- **swe-1-7-medium**：`1207.7214#1` cs 2→0 + math 违例 + S1 丢 `\`；加上小样本时代丢过行首 BIBITEM——速度全场最快但可靠性不配当默认。
- **swe-1-7**：契约 96% 不差，但 reasoning 方差失控（p95 22k 字符、单点 120k/125s），批量管线无法预算。
- **swe-2-medium 的 19 次 ord 软信号全部是人肉抽查通过的合法换序**——它的失败集里没有一个真伤。

## 5. 最终推荐

```
默认:      swe-2-medium      free→2026-10-16  100% 契约 / 5.9s / rsn~100 / out~134
备选:      swe-2-high        free→2026-10-16  99% / 10.1s（quality 升级档）
窗口期快选: glm-5-2          free→2026-09-16  91% / 4.1s —— 只在小窗口内当速度档，且必须配重试阶梯
修复器专座:  swe-2-max        free→2026-10-16  reasoning 最深，给 undefined_cs LLM 修复器兜底
禁用:      swe-1-7-medium（契约事故史）、swe-1-7（rsn 爆炸不可预算）
付费对照:  glm-5-3-low $1.4/$4.4、claude-sonnet-5-medium —— BYOK/对照组，不进默认链
```

**运行期纪律**：免费集是 promo 制的——client 启动时拉 `/panel/api/models` 按 `cost_tier=="free" && promo.active` 动态筛 + `/v1/models` 求交 + 探活；promo 到期（09-16 GLM/SWE-1.7 先行）自动降级到备选链，**不得硬编码免费集**。

## 6. 契约判定的修订（沉淀给 validator）

1. `ph_order` 从硬判据降为**软信号**（合法中文换序占违例 ~95%）；保留硬性的只有"结构占位符脱离其文本位"（BIBITEM 类，需专项检测）。
2. `cs_dropped`（脆弱命令 src→zh 计数差）升**硬判据**——本次抓到全部真编译炸弹（`\和` 熔合）。
3. validator 已知盲区状态：丢命令方向已在本 bench 补丁层覆盖（`cs_dropped`）；长度比下界 0.3→0.25 待上游修。
4. 本轮残余不可见面：占位符跨段迁移（chunk 边界处 BIBITEM 被挪出条目区）未观察到但无专项检测；译文质量层（术语一致性/学术腔）仍需人工盲评兜底——`out_*/results.jsonl` 留了全部 src/zh 原文可抽查。
