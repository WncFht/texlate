# 翻译成本模型：语料分块统计与 token 估算

> 数据来源：`tmp/exp/costmodel/chunk_stats.py`（产物 `stats.json`，同目录）。
> 口径：39 篇 arXiv 语料，每篇取主文件 → `\input`/`\include`/`\subfile` 展平 → `bench/py/miniscanner.py` 产出 chunks。
> 生成日期：2026-09-14。

## TL;DR

- 一篇典型论文（p50）：**~210 个 chunk、~7.5 万字符源文**；按任务书协议（<300 字符入批、≤2000/批）**总 token ≈ 9.1 万/篇**，与 hjfy「约 10 万/篇」锚点几乎重合（低 ~9%）。
- BYOK 单篇成本（批处理后）：**qwen-turbo 档 p50 ≈ ¥0.036（万篇 ¥360）**；deepseek-v3 档 ≈ ¥0.12（万篇 ¥1,200）；gpt-4o-mini 档 ≈ ¥0.20（万篇 ¥1,950，≈$270）。
- hjfy「3 亿 token/万篇 ≈ ¥140」隐含 ~3 万计费 token/篇，比我们任何方案低 ~3×——最可能的解释是 **prompt 缓存命中**（我们的开销模型里 prompt 摊销占输入的 68%）+ 跳译部分（参考文献/附录）。
- 批处理协议可行：平均 ~15 chunk/批，请求数压到 chunk 数的 0.38×。但 **<300 阈值太保守**：全量 chunk 入批（≤8000 字符/批）可把总 token 再降 ~40%（p50 9.1 万→5.4 万），请求数降一个量级（6,632→685）。

## 2. Token 估算

模型常量（见 `chunk_stats.py` 头部）：

- 拉丁文本 `chars/4 ≈ tokens`；中文输出 = 源 token × 1.5。
- 每请求开销 = **400 tok**（system prompt + 指令摊销）；批内每 chunk 序号/分隔符 envelope = 10 tok（in/out 各计一次）。
- 批处理协议（任务书口径）：**<300 字符 chunk 顺序贪心入批，每批 payload ≤2000 字符；≥300 字符 chunk 单独一请求**。

| 口径             | 每篇 input | 每篇 output |                                  每篇 total | 说明                                   |
| ---------------- | ---------: | ----------: | ------------------------------------------: | -------------------------------------- |
| 纯文本（下限）   |   p50 ~19K |    p50 ~28K |                                    p50 ~47K | 仅 chunk 字符，含占位符字面量          |
| 批处理后（协议） |   p50 ~62K |    p50 ~30K | **p50 91,465 / p90 276,971 / mean 162,103** | 本报告基准                             |
| 不批处理         |  p50 ~103K |    p50 ~30K |                                 p50 134,826 | 每 chunk 一请求，400 tok 摊销×n_chunks |

（in/out 的 p50 与 total 的 p50 分别取自不同论文的中位数，不相加。）

关键观察：

- **开销主导输入**：协议批处理后 prompt 摊销仍占输入 token 的 **68%**（全语料 4.16M 输入中 2.83M 是开销）。原因：≥300 字符的 chunk 占 34% 且全部单发——5,873 个 solo 请求贡献了总请求数（6,632）的 **89%**，每发都背 400 tok。
- 请求压缩：17,268 chunks → 6,632 请求（0.38×），平均 ~15 chunk/批，每篇请求数 p50 ≈ 89。
- 敏感性：把「全部 chunk 入批、≤8000 字符/批」后，请求数 6,632→685，输入降到 1.78M（开销占比 25%），每篇 total p50 **5.4 万**。批阈值是成本的最大杠杆。

不批处理时 qwen 每篇 p50 升至 ¥0.051；全量激进批（≤8000/批）降至 ¥0.025。

**与 hjfy 锚点对比**：

- hjfy「约 10 万 token/篇」↔ 我们 p50 total **9.1 万**：基本一致，略低 ~9%。说明分块 + 占位符方案在 token 量级上没有劣化。
- hjfy「3 亿 token / 万篇 ≈ ¥140」隐含 **~3 万计费 token/篇**——比我们协议口径低 ~3×，甚至比纯文本口径（4.7 万）还低。两个锚点本身不一致（10 万 vs 3 万/篇），可能解释：
    1. **prompt 缓存**：qwen/doubao 均有隐式 context caching，重复 system prompt 命中后输入近零成本——我们的开销项（占输入 68%）在他们的账单里可能几乎不存在；
    2. **跳译范围**：参考文献/附录/致谢等可能不送译（我们的 main 口径全译）；
    3. 「10 万/篇」可能是含重试/失败/预热的处理量口径，而非计费口径；
    4. 占位符占比：我们 chunk 文本 ~18% 是 `[[MATH_n]]` 等占位符字面量，计费但不产生译文——若 hjfy 的 10 万/篇只算译文侧，差距部分来自这里。
- 结论：同样用 qwen-turbo 档单价，BYOK 翻一篇 ≈ **¥0.03–0.07**（p50 ¥0.036，书级长文到 ¥0.5+），与 hjfy 的成本同数量级、高 ~2–4×；差距主要由 prompt 摊销和全量翻译范围造成，可通过缓存复用 + 激进批处理 + 跳译策略压缩到接近其水平。

## 4. 批处理协议验证

- 模拟规则：chunk <300 字符 → 按序贪心塞入 ≤2000 字符的批；≥300 → 单发。
- 结果：全语料 17,268 chunks → **6,632 请求**；批内平均 **15 chunk/批**（各篇 11–25）；每篇请求数 p50 89 / mean 170。
- 可行性 OK，但注意两点：
    - ≥300 字符 chunk 约占一半，全部单发 → 请求数主要被它们决定；放宽到「全量入批 ≤8000 字符」请求数再降 ~10×。
    - 存在超大原子 chunk（见 §5），生产上需加「超阈值 chunk 二次切分」策略，否则单请求可能超模型上下文或显著拖尾。

## 5. 过程发现（喂给 miniscanner/管线设计的输入）

1. **裸 `\input name` 不展开**：1502.01589 用 plain-TeX 风 `\input macros.tex`，`flatten_inputs` 只认 `\input{...}` → 原文只产出 1 chunk。已在本脚本 shim（归一化为带括号形式）修复至 529 chunks。
2. **`\subfile{}` 不展开 + `\end{document}` 截断**：2609.06443 用 subfiles 包，每个子文件自带 `\begin/\end{document}`；即使展开，扫到子文件的 `\end{document}` 会提前终止。shim 后 7 → 335 chunks。**建议 miniscanner 支持 `\subfile`，且 `\end{document}` 命中后仅在顶层截停**（或展平时剥子文件壳）。
3. **巨型原子 chunk**：2609.06443 有一个 **109,090 字符 chunk**——`\version{}{...}` 宏（`\ifbool` 二选一）把整个附录装进参数，被按透明参数内联成一个 run；1207.7214 有 76,882 字符块（ATLAS 作者名单长段）。需要「chunk 超阈值切分/宏参数展开上限」策略。
4. **零文本论文**：1412.6980 的 tex 只是 `\includepdf` 包装（正文在 PDF 里），0 chunks——真实 e-print 存在无 TeX 正文的情形，管线要能优雅跳过。
5. **书级语料拉高均值**：1106.1445（QIT 讲义，1.44M 字符/5,572 chunks）、1612.09375（范畴论讲义，34 万字符）是书籍不是论文——mean 162K 被它们抬高，**p50 91K 才代表典型期刊论文**。
6. **all_files 上界**：目录全部 .tex 独立解析合计 7.40M 字符（main 口径 1.39×），差额来自 psets/文档类文件/未被主文件引用的 tex——产品按 main+flatten 走是对的。

## 6. 结论

- BYOK 用户翻一篇典型论文的真实成本预期：**qwen-turbo 档 ~¥0.04（3–7 分），deepseek-v3 档 ~¥0.12–0.22，gpt-4o-mini 档 ~¥0.20–0.36**；极长文档（讲义/书）可达 ¥0.5–1.4（qwen）。
- 与 hjfy 经济性对比：我们 token 量/篇与「10 万/篇」锚点吻合；但其 ¥140/万篇隐含 3 万/篇计费——同价模型下我们高 ~2–4×，**差距不在解析质量而在计费结构**：prompt 摊销（我们模型占输入 68%）在缓存命中后趋零、跳译非正文内容、更大批次是追平的关键路径。
- 协议建议：批阈值从 <300 放宽到全量入批；单批上限按 token（而非字符）控制 ~2000–4000 tok；加超大 chunk 切分；miniscanner 需补 `\subfile`/裸 `\input`/`\end{document}` 截断三处展开缺口。
