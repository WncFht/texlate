# 官方 PDF vs 自编译 baseline 保真度对拍

> **结论**：官方 PDF 与我方自编译 PDF 之间**锚点不可借用**——15 篇中仅 1 篇同名锚同页率 ≥0.9，13/15 页数漂移（Δ 中位 +13），锚命名体系亦分歧（`equation.3.1` 式 vs 平铺式 vs 纯数字锚）。官方 PDF 经 pdfTeX/GS/pikepdf 后处理且首页带一行 `arXiv:{id}v{N}` 页眉戳。
> **状态**：时点证据（2026-09-14 口径）。本文原建议「en 侧渲染用官方 PDF + 文本级对齐」；**落地实际走向另一条更简的路**——server 编译链自产 `en.pdf`（与 zh.pdf 同引擎同管线），双侧 named-dest 命名天然同构，`align.py` 直接做锚名配对+最大权单调子序列。本文的「跨引擎锚不可借用、分页普遍漂移」结论正是否决「复用官方 PDF 做原文侧」的证据。
> **日期**：2026-09-14 取证，2026-09-20 重订入库

## 1. 方法与配对

pypdf 提取页数 / named destinations（剥前导 `/` 归一）/ 文本 / metadata；文本相似度取官方首页+中位页，对 baseline 同序号页（same_index）与 ±3 页窗内最优（aligned）各算一次 difflib ratio。15/15 配对成功；baseline 取主文档 PDF（顶层含 `\documentclass` 的 .tex 同名 PDF）。

baseline 数据坑（选定件质量警告）：0807.3917 engine 版 `main.pdf` 只 3 页（官方 23 页，tectonic 截断，pstricks+IEEEtran 雷区）；1810.04805 compile 目 3 页/12 锚但 fixloop 目 17 页/144 锚完整版——**compile 与 fixloop 的 "baseline" 语义不一致**；2305.14335 两次自编译页数即不一致（17 vs 13，官方 12）——分页对字体/宏包版本极敏感。

补充观察：

- **锚命名分歧模式**：官方有而 baseline 无的多为 `equation.3.1` 式（section 限定编号），反之为 `equation.1` 平铺式——同一源码两边 `\theHequation` 展开不同。1207.7214 baseline 是纯数字锚名（`hypertexnames=false` 风格），与官方 `cite.*/Hfootnote.*` 体系完全不可通约；math/0404188 baseline 连 `/Names`/`/Outlines` 都没有（无 hyperref 锚）。
- **官方 producer 谱系**：pdfTeX-1.40.12~25 为主 → 老的走 dvips+Ghostscript → 近年 arXiv 用 **GPL Ghostscript 10.01.2 或 pikepdf 8.15.1 重写后处理**——官方 PDF 已被 arXiv 后处理过，不是 TeX 直出（named dests 大部分幸存）。
- **arXiv 戳**：官方 PDF 只在**首页页眉**注入一行 `arXiv:{id}v{N} [{cat}] {date}`（15/15 如此）；无整页水印、无逐页戳。
- 中位页 same_index 相似度普遍 ~0 是分页漂移假象：±3 页窗对齐后 2005.11401 升到 1.00、2106 升到 0.63——内容同源只是页对不上。

## 3. 结论

### 保真度分布

- **完全对齐**（页数相同+同名锚同页率 ≥0.9）：仅 1706.03762 一篇（1/15）。
- **锚名兼容但页位漂移**（recall ≥0.75 但同页率 <0.6）：8 篇——hyperref 命名幸存但分页 ±1~+20 页漂移，锚→页码映射不可借用。
- **锚体系不兼容/无锚**：3 篇（baseline 截断/数字锚名/无 hyperref）。
- **中间档**：3 篇（巨型分叉 774→976 页、截断、编号体系漂移）。
- 分页漂移是普遍现象（13/15 页数不等，Δ 中位 +13）：xetex/xdvipdfmx 与 pdftex 字体度量差异 + arXiv 后处理共同导致；自编译件间也互漂（2305 两个 baseline 差 4 页）。

### 对选型的影响（落地路径）

原文侧有两个候选：官方 PDF（用户期望看到的版本，但锚/页码与我方产物不可通约）与自编译 en.pdf（与 zh.pdf 同引擎同管线 → 锚名天然同构，named-dest 直接配对）。本实验否定了「跨引擎借锚」路线；落地选择了**自编译 en.pdf**——同源对齐问题消失，`align.py` 的锚名配对+单调子序列在双 PDF 间成立；官方 PDF 不参与阅读器渲染面。残余用途：官方 PDF 作 en 侧展示「原版观感」的潜在可选视图，以及文本级对拍的参照物。

### arXiv 水印/戳

官方 PDF 只有首页页眉一行文本戳，无图形水印。若未来引入官方 PDF 作展示面：**首页文本对齐前先剥 `arXiv:\S+v\d+.*` 行**（否则官方首页恒定多一行）；zh 侧源码编译本就不带戳，加页眉戳是可选装饰而非正确性问题。
