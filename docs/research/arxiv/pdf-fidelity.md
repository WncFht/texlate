# 官方 PDF vs 自编译 baseline 保真度对拍

> 目的：定阅读器原文侧选型——用 arXiv 官方 PDF 还是自编译 PDF；滚动同步锚能否跨两侧复用。
> 数据：`tmp/exp/pdf-fidelity/compare.json`（由 `tmp/exp/pdf-fidelity/compare.py` 生成，可重跑）。
> 方法：pypdf 提取页数 / named destinations（剥前导 `/` 归一）/ 文本 / metadata；文本相似度取官方首页 + 中位页，
> 对 baseline 同序号页（same_index）与 ±3 页窗内最优（aligned）各算一次 difflib ratio。

## 配对与 baseline 来源

15/15 全部配对成功（无 unpaired）。主文档判定规则：顶层含 `\documentclass` 的 `.tex` 同名 PDF，命中率 15/15。
优先级 engine/work > work_compile/baseline > work_fixloop/baseline。

**数据坑（选定 baseline 的质量警告）**：

- `0807.3917`：engine 的 `main.pdf` 只有 **3 页**（官方 23 页）——tectonic 编译截断产物（`_tect_out/` 里只剩 log）。pstricks+IEEEtran 是已知雷区。
- `1810.04805`：work_compile 的 `main.pdf` 只有 **3 页/12 锚**（官方 16 页/143 锚），但 work_fixloop 同名文件是 **17 页/144 锚**的完整版。compile 与 fixloop 的 "baseline" 语义不一致，fixloop 目录里的反而是修好的完整编译。
- `2305.14335`：engine 版 17 页、work_compile 版 13 页、官方 12 页——我们自己两次编译页数也不一致，分页对字体/宏包版本极敏感。

补充观察：

- **锚命名分歧模式**：官方有而 baseline 无的多为 `equation.3.1` 式（section 限定编号），反之为 `equation.1` 平铺式——同一源码两边 `\theHequation` 展开不同，编号策略/class 版本有漂移。`1207.7214` baseline 是纯数字锚名（`hypertexnames=false` 风格的 `'0','1',...`），与官方 `cite.*/Hfootnote.*` 体系完全不可通约。`math/0404188` baseline PDF Root 只有 `/Pages`+`/Type`，连 `/Names`/`/Outlines` 都没有（无 hyperref 锚）。
- **官方 producer 谱系**：pdfTeX-1.40.12~25（绝大多数）→ 老的走 dvips+Ghostscript SVN 8.62（math/0404188）→ 近年 arXiv 用 **GPL Ghostscript 10.01.2 或 pikepdf 8.15.1 重写后处理**（0807/1207/2602/2609×2）。即官方 PDF 已被 arXiv 后处理过，不是 TeX 直出——但 named dests 大部分幸存（pikepdf/GS 保留名字树）。
- **arXiv 戳**：官方 PDF 只在**首页页眉**注入一行 `arXiv:{id}v{N} [{cat}] {date}`（15/15 均如此，strict 正则命中=首页）；其余 `arXiv:` 命中全是参考文献引用。无整页水印、无逐页戳。baseline 侧 0 戳。
- **中位页 same_index 相似度普遍 ~0** 是分页漂移假象：±3 页窗对齐后 2005.11401 升到 1.00、2106 升到 0.63、2308 升到 0.50——内容同源，只是页对不上。首页 sim<0.9 的（2106/2305/2501/2609×2）多为 baseline 多了前置页（目录/符号表/front matter 版本差异），2501.14787 baseline 首页是符号索引页而官方是标题页。

## 结论

### a) 保真度分布

- **完全对齐**（页数相同 + 同名锚同页率 ≥0.9）：**仅 1706.03762 一篇**（1/15）。同页率第二高的 1810.04805（0.92）是 3 页截断件的 12 锚小样本，不算数。
- **锚名兼容但页位漂移**（recall ≥0.75 但同页率 <0.6）：1512.03385、2005.11401、2106.09685、2305.14335、2308.07483、2501.14787、2602.06617、2609.06443 —— **8 篇**。hyperref 命名幸存，但分页普遍 ±1~+20 页漂移，锚→页码映射不可借用。
- **锚体系不兼容/无锚**：0807.3917（baseline 截断 +0 锚）、1207.7214（数字锚名）、math/0404188（baseline 无 hyperref 锚）—— **3 篇**。
- **中间档**：1106.1445（recall 0.39，774→976 页巨型分叉）、1810.04805（baseline 截断）、2609.08578（recall 0.52，theorem/definition 编号体系漂移）—— **3 篇**。
- 分页漂移是普遍现象（13/15 页数不等，Δ 中位数 +13）；xetex/xdvipdfmx 与 pdftex 字体度量差异 + arXiv 后处理共同导致。自编译件间也会互漂（2305 两个 baseline 差 4 页）。

### b) 阅读器原文侧选型建议：**混合——en 用官方 PDF，同步锚全从我方产出侧取**

1. **en 侧渲染用官方 PDF**。它是用户期望看到的版本（含页眉戳、期刊版式都对）；我们的 baseline 有 2/15 截断、1/15 无锚、分页普遍漂移，直接当原文侧会引入"翻译对了但原文不对"的新型错误。
2. **滚动同步不要尝试"官方锚 ↔ 我方锚"名对齐**。同页率 ≥0.9 的只有 1/15；锚名 recall 虽有一半 ≥0.9，但页位已漂。正确做法：zh 侧（我们编译的中文 PDF）的锚/段落位置为事实源，en 侧官方 PDF 里用**段落文本/章节标题对齐**（E18 结论的正向印证：锚保留率只能在我方管线的 zh PDF 内部保证；跨到官方 PDF 必须走文本级对齐）。`page.N` 锚在官方 PDF 里倒是普遍存在（每页一个），可作"翻到第 N 页"的粗粒度兜底，但页码与 zh 侧不对应，只能经对齐表换算。
3. baseline 资产别扔：zh 编译管线产出的 en-side 自编译件仍可用于**对齐计算**（它与官方同源、文本 sim 高 → 做文本级 anchor mapping 的中介），只是不作为阅读器展示面。

### c) arXiv 水印/戳的对称性影响：**基本无影响，但首页首行要做 strip**

- 官方 PDF 只有**首页页眉一行文本戳**（`arXiv:{id}v{N} [{cat}] {date}`），无图形水印、无逐页标记。视觉上属用户预期，**不需要剥离**；给 en 侧自编译件注入对等戳也没有必要（选型 b 已决定 en 展示面=官方件）。
- 对管线唯一实际影响：**首页文本对齐前先剥掉 `arXiv:\S+v\d+.*` 行**，否则官方首页首行恒定比任何自编译件多一行（本实验中 stripped vs raw 相似度差 <0.04，影响小但确定性存在）。
- zh 侧无对称性问题：我们的 zh PDF 从源码编译，本就不带 arXiv 戳；若产品上想还原"官方感"，加一行页眉戳是可选装饰而非正确性问题。
