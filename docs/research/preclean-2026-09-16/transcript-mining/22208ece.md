### A5. 端口/PID 取证——只杀自己的 vite（#532→#545）

`pkill -f "vite.*5174"` 失败（exit 144，vite cmdline 不含端口）。正确姿势：

```bash
ss -tln | grep -E "5173|5174"; pgrep -af vite
for pid in $PIDS; do echo "== $pid =="; cat /proc/$pid/cmdline | tr '\0' ' '; ps -o lstart= -p $pid; done
ss -tlnp | grep -E "5173|5174"   # users:(("vite",pid=...)) 定位端口属主
kill <我的PID> && sleep 1 && (ss -tln | grep 5174 || echo "5174 free")
```

用 `ps -o lstart=` 的启动时间区分「我 13:13 起的」vs「别会话 09:17 起的」，只杀自己的。

## C. 新运维经验（前端调试/验证手法）

1. **vite 端口漂移必须按日志实测**：`Port 5173 is in use, trying another one...` → 实际在 5174。readiness 轮询写死端口会打到别的会话的服务上（本例 5173 是另一会话的 vite，curl 到的是真后端数据）。正确流程：起服 → tail log 取 `Local: http://localhost:PORT/` → 用该端口 curl `/api/health` 验 `version:"mock"`。
2. **playwright-core 与浏览器缓存版本解耦**：npm 包版本期望的 chromium revision 与 `~/.cache/ms-playwright/` 实存版本常不一致；`executablePath` 显式指到缓存里的 `chrome-linux64/chrome` 即可跑（版本差异在本场景无影响）。
3. **Read 工具可直接看 PNG 截图**——e2e 产物截图直接 Read 进上下文做视觉确认（#459-#462、#481-#486）。
4. **SSE 增量帧的正确性要用时间序列断言**：对「累积型 UI」数两次 DOM 数量断言单调性，比单帧断言更能抓回归。
5. **多代理改同一前端的降冲突手段**（A-impl prompt 全文见 `get u:ce0166d7`）：①文件级归属白名单+黑名单写死在 prompt；②共享契约先行（接口签名、i18n 键名、CSS 类名清单 leader 定好再下发）；③各自跑 tsc/eslint 时约定「只修自己文件的错，别人的错列进报告」；④交付报告强制含「留给 CSS wave 的类名清单」。
6. **交付报告≠文件实况**：B-impl 交付前没读到 leader 的中途修正消息，报告内容与实际文件不符——leader 用 grep 抽查关键特征串核实后再发 delta 清单（#292-#302）。审计 agent 也抓到比 leader 预判更深的 bug（manifest db-kind 键、documents 可缺侧），中途 SendMessage 修正分工是必要的。
7. **需要后端跟进的契约类坑值得留档**：docx/epub 被 202 接受但 `_run_doc` 未接线注定 fault、glossary UI 收内容后端要路径（功能 no-op）、EVENT_CAP=2000 截断 SSE 回放、local 模式 CSRF origin 检查会让局域网主机名访问全 403——都写在会话结尾报告里（#550）。
8. **run 技能自带的 playwright 示例**提到 `chromium-cli`（bundled skill 文件 `/tmp/claude-1000/bundled-skills/2.1.272/.../run/examples/playwright.md`），本机没装 → 回退 playwright-core 手写脚本，效果一样。
