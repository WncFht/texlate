## C. 新运维经验

1. **arXiv 取源有日预算**：每篇 = HEAD+GET 2 请求，日预算 ~180 发 → 单轮 `--limit 85` 封顶，次日 durable cron 续跑（rate limiter 带 host 限速桶+(host,path) 断路器：连续 2×429/406 park 30min）。
2. **hot 层 pdf_only 率 ~15%**（13/85 跳过）——高引论文有相当比例无源码（只挂 PDF），抽样配额要打余量。
3. **Semantic Scholar 无 key 即 429** → 热度排序源改用 OpenAlex（`sort=cited_by_count:desc` + `sample=` + cursor，`User-Agent` 带 mailto 进 polite pool）。
4. **巨型论文真实存在**：2504.01669 单工程 47MB/1893 chunk，翻译 ~25min——e2e `--time-budget` 要留够（demo 给了 2400s）。
5. **网关 429 是瞬时限流**：probe 失败先换端点（100.105.212.52 ↔ 127.0.0.1 本机均通）再判死。
6. **e2e_real_bench 有 preflight**：0 网络一致性检查 + 模型 probe，烧配额前拦半成品。
7. **fixloop 只在 fail 上跑**：partial 有 PDF，halt_on_error + 树改写（vendored sty/tlmgr 装包）会把已有 PDF 弄丢——"修 warning 级判据"不是 fixloop 的活。
8. **后台跑批模式**：`nohup uv run python bench/py/... > /tmp/x.log 2>&1 &` + `sleep 115; tail` 轮询 + state.json completed 计数做进度条。
9. 语料 gitignore 是**白名单制**（`bench/corpus_v3/.gitignore`：`+ *` 全ignore，`!manifest*.jsonl` 等逐项放行）——新增清单文件要手动加白名单。
10. fish 下 `command grep` 强制走系统 grep 避开 ugrep alias（仓内命令已按此写）。

## D. 建议产品化

1. **`texlate demo` / `scripts/demo.sh` 值得固化**：本次 demo 序列（fetch→parse→run→pdftotext 验 CJK→e2e_real_bench 单篇真翻）全是现成产品面，只差一个固定入口。选 2105.11479 这类 21KB `article` 小品做默认样例（5 段全绿 ~25s mock / ~25s 真翻）。价值：新人 onboarding + 发版冒烟。
2. **网关 doctor 值得进 CLI**：`list_models + cost_tier 过滤 + 双端点探活 + chat probe` 这套片段在会话里手拼了 4 次。`tools install-tectonic` 已有先例——`texlate tools doctor`（或 `gateway models`）收纳最自然。
3. **OpenAlex 抽样已沉淀成 build_hot_layer.py**，无再包装必要；但「日预算 85/轮 + durable cron 续跑」模式可抽成通用 fetch-resume 约定（后续扩语料层都受用）。
4. **`_xlat_state/{sid}/state.json` completed 计数**是最简进度探针——若 server 侧要暴露任务进度，同一数据源可直接复用（现在 server 走 SSE 任务队列，bench 侧可读取 state.json）。
5. 不建议固化：chunks.jsonl 检阅 one-liner、语料 survey for-loop——一次性侦察性质，README/文档提一句即可。
