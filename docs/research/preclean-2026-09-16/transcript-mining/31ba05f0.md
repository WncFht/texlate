### A1. 对「仅 git 跟踪文件」跑 cloc 的正确姿势

```bash
# 探测工具
which tokei cloc; git ls-files | wc -l        # 本机有 cloc 2.10，无 tokei；621 个跟踪文件

# 失败路径：--stdin 不接受 ls-files -z 的输出，静默空结果
git ls-files -z | cloc --stdin --by-file --quiet   # → 无输出，别用

# 可用路径：先落盘文件清单，再 --list-file
git ls-files > /tmp/texlate-files.txt && cloc --list-file=/tmp/texlate-files.txt --quiet | tail -45
```

### A2. 分行数 drill-down 一套拳（数据文件 vs 手写代码分离）

```bash
# 找出行数最大的 JSON（定位"假代码量"——生成的数据快照）
git ls-files '*.json' | xargs wc -l 2>/dev/null | sort -rn | head -15

# 按顶层目录统计行数（剔数据文件）
for d in src tests web bench docs scripts bench/fixtures; do
  echo "=== $d ==="
  git ls-files "$d" | grep -v '\.json$\|\.jsonl$\|\.csv$' | xargs wc -l 2>/dev/null | tail -1
done

# 按子目录统计文件数（看 bench 构成）
git ls-files bench | grep -v '\.json$\|\.jsonl$\|\.csv$' | sed 's|/[^/]*$||' | sort | uniq -c | sort -rn | head -15

# 未跟踪（未提交）新代码也算开发量
git ls-files --others --exclude-standard | grep -v 'results/\|\.json$\|\.jsonl$' | xargs wc -l 2>/dev/null | sort -rn | head -20
```

## C. 新运维经验

1. **cloc 口径陷阱**：本仓 `bench/results/` 入库了 158 万行 JSON 评测快照，裸 `cloc` 会把数据当代码。统计开发量必须先 `git ls-files` 圈定跟踪集，再剔 `*.json/*.jsonl/*.csv`。
2. **`cloc --stdin` 与 `ls-files -z` 不兼容**（cloc 2.10，静默空输出），`--list-file=` 才是对的入口。
3. **未跟踪文件要单独算一档**：`git ls-files --others --exclude-standard` 抓到了 3.4k 行未提交新代码（export/epub、新测试），只看跟踪文件会漏。
4. 回答「项目多少代码」时给三层数字最有信息量：核心产品代码 / 含 bench+docs 总量 / 生成数据量（剔除项）。
