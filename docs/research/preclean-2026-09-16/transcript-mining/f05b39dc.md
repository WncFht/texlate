## C. 新运维经验

1. **进程→会话归因的完整套路**：`ss -tnp` 拿 PID → `ps` 拿 cmdline（找指纹字符串）→ `/proc/PID/cwd` 圈项目 → `find ~/.claude/projects/<proj> -newermt` 圈活跃 transcript → grep 指纹定位 sid → `grep 'This session is'` 拿 fleet 名 → `SendMessage` 送达处置方案（附 PID/证据/重启指引）。`/proc/PID/fd` 抓 jsonl 这条路本次是空的——transcript 不常驻 fd。
2. **nft base-chain 的 accept 是链局部的**：同 hook 上独立 base chain accept 挡不住别的 base chain（firewalld/ts-input 照样跑）。要让规则先生效必须插进**同一个** chain 里、在 jump 之前。
3. **tailscaled `ts-input` 反欺骗**：`ip saddr 100.64.0.0/10 iifname != "tailscale0" drop`——本机 REDIRECT 代理的 un-NAT 回包 src=tailscale IP、iif=lo，正好撞死在这条上。这是本次 ConnectionRefused 的根因。且 tailscaled 每次重启重插 jump，要用 systemd drop-in ExecStartPost 兜底重钉。
4. **`srcnat` priority 只在 postrouting hook 合法**，output hook 不行（`invalid priority expression value`）。
5. **fail-open 设计**：redirect 单元 `BindsTo` 代理——代理死了 nft 规则自动撤，出向流量恢复直连，不会搞挂全场。
6. **`ss -K` 可强杀单条 TCP 连接**（`ss -K dst <ip> dport = <port>`），用来逼存量直连连接重握手走代理，不用杀进程。
7. **改动防火墙前先想好回滚**：本次中间态把全部会话打 ConnectionRefused，用户来问"是你搞的吗"——答案是要能秒级 `nft delete table` 恢复。调试规则全带 comment/counter 便于事后清扫。
8. **sudo 密码管道**：`echo 240127 | sudo -S <cmd>`；循环里注意 `sudo -S` 在后台/非 tty 会报 "a terminal is required"——要么包 `sudo -S sh -c '...'` 一次做完，要么先 `sudo -v`。
9. **并发参数的运行时不可改性**：e2e_real_bench 的 concurrency 在 PipelineConfig 启动时定死，降并发必须重启进程；`results.json` 逐篇落盘 + `_paper_done` 断点续跑使重启零损失——**bench 脚本的可恢复性是敢让属主重启的前提**。
10. **`tcpdump` 本机没装**（archbox）；nftrace 是零依赖替代品且更贴规则语义。
11. **archbox 上 tailscale 本机 IP 在 `lo` 上**（`ip route get 100.121.76.120` → `local ... dev lo`），所以 lo 上的 tailscale-source 包必须显式放行。
