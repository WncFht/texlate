## C. 新运维经验

### C1. 多会话/多 agent 同仓协作（本会话是三方会战现场：本 fleet 12 + texlate-1d 13 + texlate-1e ~8）

1. **staged 文件会卡别人 commit**：pre-commit 的 ruff-check 扫整个 index，我 staged 的 7 错文件把 texlate-1d 的 commit 拦了——agent 交付先过 `ruff check` 再 `git add`，或多会话期间尽量即验即提。
2. **commit 撞车**：两边同时 commit，pre-commit stash restore 冲突会静默回滚我的提交（输出被截断看不见）。对策：`git commit` 后必跑 `git log -1 --format="%h %s"` + `git status --short <files>` 确认落没落。
3. **文件级冻结协调**：rules.yaml/builtins.py 是两个 fixer 的 append-only 共享区，第三个写者 tail-append 锚点必撞 Edit——先广播"冻结"，交付后"解冻"。
4. **跨会话 SendMessage 走 uds sock**（`to=uds:/run/user/1000/cc-socks/*.sock` 或对名字），换 scope 清单+撞车确认；`ListAgents` 看 roster。
5. **shell cwd 漂移**：前面 `cd bench/corpus_v3` 后 `git add docs/...` 相对路径炸掉（exit 128）——长会话里 commit 前 `cd` 回 repo 根或用绝对路径。
6. **markdownlint 改写会 fail 一次**：重写暂存内容后需重新 `git add` 再 commit（本仓既定行为）。
7. **agent prompt 归属写死**：「你只许改这一个文件」式 prompt，rules.yaml 扩列/builtins/l0 三个 fixer 零互踩。
8. **subagent 写不了报告 .md**（harness 拦 `bench/results/**/SUMMARY.md`）——它们把全文 SendMessage 给 leader，leader 代落盘。
9. **交付验收套路**：`git diff --stat` 看范围 → `ruff check + format --check` → `pytest -x -q` → 提交 → `TaskStop` 关 agent。

### C2. 语料/数据工程

10. **item-index.csv 的 size 字段会过期**（9901_001/0408_001 差 0.3-0.6MB，按索引续传会 416）——权威 size+sha1 走 IA metadata API。
11. **IA item-index 止于 2010**（2020-10），e-band（2021+）无 IA 源只能走 tiger（HF LFS）。
12. **append 模式 manifest 会带入冒烟残留**：corpus-expand 的 +60 astro-ph 超收就是 12:56 smoke 批 append 进最终 manifest——QC 要按时间戳查归因。
13. **签名可分辨度定规模**：n ≈ 3/p（要看到发生率 p 的签名 ≥3 次）。1259→0.24%，5000→0.06%，10000→0.03%。
14. **抽样按 stratum_cell（era×cluster）配额 + 故障率加权**（n100 bad 率：a .74/b .83/c .71/d .45/e .61），新增量压向最可能暴露问题的层。
