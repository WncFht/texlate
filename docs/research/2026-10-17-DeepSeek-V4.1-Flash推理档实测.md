## 结论

`2610.11291` 经 TeXlate 当前翻译链分别使用 `low`、`high`、`max` 三档推理运行，三组均为 `done`，124/124 块完成且无失败。每篇均开启自动术语抽取、使用并发 4，并关闭编译修复的 LLM 旁路；唯一处理变量是 Responses 请求的 `reasoning.effort`。

max 的输出 token 是 low 的 2.89 倍。

## 输出与产物

三组原文均为 40,069 字符。译文字符数 low/high/max 分别为 16,688/16,996/17,144，中文字符数为 8,700/9,071/9,214。译文的 SHA-256 前 12 位分别为 `ae3435285c42`、`aae9dd334aef`、`4fc7b0b89740`，三档产出并非逐字相同。

三组的 `zh-src.zip` 均通过完整性检查，`zh.pdf` 分别为 27/26/26 页。max 运行中出现两次 `finish_reason=length`，TeXlate 随后以 32K 输出预算重试并完成，最终任务仍是 `done`。

## 测量口径

token 数取 TeXlate `task_usage`，由每次成功 Responses 返回值累计。low 组的 ccLoad 账本在同任务窗口内有 81 条与 TeXlate 完全一致的 `thinking_effort=low` 记录，输入 68,400、输出 94,216，缓存读取为 0。

high 和 max 的 ccLoad 时间窗混有同一 ccLoad 上的其他客户端请求，不能把窗口总和直接归给本任务；其中记录到的缓存读取也不能按时间窗归属。任务 token 以 TeXlate 的逐任务 usage 为准。

2026-10-17 后续修改已让 TeXlate 把响应中的缓存读取 token 累加进 `task_usage.cached_tokens`，并在任务快照和阅读器统计条展示。该字段从修改后开始记录，不回填本次三组历史任务；它们仍只有输入、输出和调用次数。

## 解释边界

本次只测一篇论文，不能据此断言各推理档的总体质量或平均 token 用量。三组均开启自动术语抽取，因此 token 包含术语抽取与翻译调用；若产品关闭该选项，token 会变化。max 的截断重试会增加输出消耗，其他论文是否触发取决于批次输出长度与模型的停止行为。
