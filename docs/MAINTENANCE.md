# docs/ 维护规则

本文档库的唯一维护契约：写新件、改旧件、登记索引、发布前检查都先读这里。仓级入口约定见根 `AGENTS.md`；贡献者上手序见 `dev/README.md`。

## 1. 分区结构与生命周期

| 分区             | 读者   | 内容                                       | 生命周期               |
| ---------------- | ------ | ------------------------------------------ | ---------------------- |
| `guide/`         | 用户   | 安装上手、CLI、web 服务、BYOK、导出共享    | 活文档，随版本更新     |
| `spec/`          | 实现者 | 各层技术规范，**实现的唯一事实源（SSOT）** | 活文档，与代码现状对齐 |
| `decisions/`     | 所有人 | ADR 决策记录：为什么这么定                 | 只增不改（子结论改判走宿主 ADR「演变」节）；整篇作废才开新 ADR |
| `dev/`           | 贡献者 | 仓布局、工具手册、评测协议、自动化契约     | 活文档                 |
| `research/`      | 实现者 | 调研与实证档案，决策的证据层               | 写完冻结，可加状态注记 |
| `log/`           | 所有人 | 工程大事记与里程碑档案                     | 只增不改               |
| `README.md`      | 所有人 | 文档库总索引与阅读序                       | 活文档                 |
| `MAINTENANCE.md` | 维护者 | 本文                                       | 活文档                 |

## 2. 变更归层：写什么放哪

按变更性质选落点；一件变更常跨两层（如 spec + log 同步）。

| 变更                            | 落点                                                                          |
| ------------------------------- | ----------------------------------------------------------------------------- |
| 代码行为、接口、契约变化        | `spec/` 对应件，与代码同提交更新                                              |
| 用户可见行为、安装/上手路径变化 | `guide/` 对应件                                                               |
| 推翻或修正既有裁决              | 子结论改判 → 记宿主 ADR「演变」节 + 更新「现状」节与日期行，不单独占号；整篇作废 → 新 ADR 进 `decisions/adr/` + 旧文加 SUPERSEDED 横幅（不删文、不改写历史正文） |
| 新实测数据、调研、审计证据      | `research/` 对应域新文件 + 域 `README.md` 登记一行                            |
| 里程碑、审计、发布、阶段收官    | `log/` 当日目录或文件 + `log/README.md` 时间线续记                            |
| 仓布局、工具链、操作流程变化    | `dev/` 对应件                                                                 |
| 决策动机存疑但暂无新裁决        | 不动 `decisions/`；新证据落 `research/`，相关 ADR 可加注                      |

## 3. spec/ 纪律（事实源）

- `spec/` 与 `src/texlate/`（bench 件与 `bench/`）代码现状一一对齐。发现文档与代码漂移：以代码为准改文档；若判定代码该改而非文档，先记漂移再报决策，不抢先改规范。
- 规范只写「是什么/怎么约束」；实测过程、样本数字、选型对比引 `research/` 证据件，不复述。
- 引用代码写「模块 + 符号」粒度（如 `compile/engine.py::route_engine`）。行号锚点（`file.py:NNN`）只是时点快照，拆包即失效——仅用于「当时取证」语境。
- 承诺了但未实现的条目集中列在各件「未落地清单」节，不混在已落地描述里。
- 规则数、文件数这类易漂移计数优先写生成口径或指引出处，不手抄数字（历史教训：同一规则计数曾四处各不同）。

## 4. 写作格式

- 段落写在单行内，不手工折行；`##`、`###` 分层级，不用加粗伪装标题。
- 表格只承载并列事实；长篇论证用连贯段落。
- 外部来源引用用脚注：正文来源名后紧跟 `[^key]`（键为小写 ASCII 与连字符，如 `[^unarxive20]`；同一来源多处复用），行内不放裸链接；文末设 `### 参考文献` 节，逐行 `[^key]: 作者. 标题. 来源 年份. [标题或域名](链接)`。
- 日期化文件命名 `YYYY-MM-DD-<topic>.md`，日期为成文（冻结）日期——后续修订（迁移触碰、状态注记等）不改文件名，修订日期记入状态块；topic 语言与正文一致（中文文档用中文名）。非日期化主题件用稳定小写 ASCII 连字符名。
- 行内公式 `$`，行间 `$$`；表格内公式避免裸 `|`，用 `\mid`、`\Vert` 等。

## 5. 状态块与 SUPERSEDED（research/ 与 log/ 必备）

每篇调研/日志件开头带状态块：

```markdown
> **结论**：一句话可带走的判断。
> **状态**：现行 | 时点证据（YYYY-MM-DD 口径） | 已改判（→继任路径） | 已落地 | 已完成
> **日期**：YYYY-MM-DD
```

一次性终态（如 `已修复`）按实况直书即可，不必强套枚举。被后续裁决或实装取代的文档，标题下加横幅（不删文件、不改写历史正文）；SUPERSEDED 横幅可叠加于任意状态的件——`已落地`、`已改判` 件均有实例，非 `时点证据` 专用：

```markdown
> **⚠️ SUPERSEDED YYYY-MM-DD**：<什么判定已过期>。现状唯一事实源 = <继任者路径>；本文仅留<取证过程等>作历史参考，勿再据此派工。
```

时效性结论（免费额度、默认模型、配额数字）过期等同被改判，同样处理。

## 6. 敏感政策（公开发布红线）

`docs/` 随主仓公开发布。禁出现：

- 任何 key、token、密码及其形态串（含示例值）；
- 内网与 tailscale IP（`100.x.x.x`）、内部主机名；
- `~`、`/tmp/`、家目录等本机路径——产品自身路径写 `TEXLATE_DATA_DIR`、「家目录下 `.texlate/`」、「XDG state 根下 `texlate/`」这类语义形，仓内路径一律仓相对；
- 内部端口与部署细节（网关 shim、转发器、内部 systemd 实例等）；
- 个人账户信息。

LLM 网关统一表述为「内部 OpenAI 兼容网关」，不点名具体私有服务；模型名与公开 API 端点可写。开发机证据现场（`bench/results/`、`tmp/`、未入库工作区）只允许「结论已摘要进正文」式提及，不作依赖链接——fresh clone 不存在属预期。

## 7. 索引登记

- 每层 `README.md` 是该层索引：新件入库必须登记一行（文件 → 一句话内容）；删件同步删行。
- `research/` 索引按主题域分表，新域先建域 `README.md` 再登总索引；`decisions/README.md` 是全部 ADR 的索引（含状态列）；`log/README.md` 是编年时间线。
- 规范与 ADR 引用的裁决证据必须落在 `research/` 或仓内已入库路径；untracked 现场不作引用源（丢失与断链双重风险）。

## 8. 自动化写入位

- errsweep agent 的报告落 `research/errsweep/<date>-sweep.md`（完整契约见 `dev/errsweep-runbook.md`），域索引由报告方顺带维护。
- 其余自动化（daily-soak、定时任务等）不直接向 `docs/` 写件——产出落各自 results/state 区，摘要由人归档进 `log/`。

## 9. 工具链与提交纪律

- `docs/` 内 `*.md` 走主仓格式化链：markdownlint-cli2 原地改写 → md 内 python 栅栏 `ruff format` → autocorrect → prettier（git-format-staged 语义：改写暂存内容并同步工作区；改写类 hook 会 fail 一次，重新 `git add` 再提交）。细则见根 `AGENTS.md` 格式化工具链节。
- `research/` 下数据文件（csv/jsonl/svg/tex/pdf）按各域 README 口径入库；大二进制与第三方文献原件不入库。
- 多会话共仓纪律：提交只加显式文件路径，不用 `git add -A` 全仓扫；他 lane 在飞 staged 工作不卷入本 lane commit（必要时用 `GIT_INDEX_FILE` 私有 index 提交）。
