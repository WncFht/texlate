# 文档维护契约

采用 [文档分工](../.agents/references/documentation.md)、[文字维护](../.agents/skills/maintain-prose/SKILL.md) 与 [Notes 生命周期](../.agents/references/decision-notes.md)。这些规则适用于新旧材料；不保留旧 ADR、整目录冻结或永久保留过程记录的例外。

## 内容归属

| 位置             | 内容与更新方式                                                 |
| ---------------- | -------------------------------------------------------------- |
| `guide/`         | 用户完成任务需要的前提、步骤、结果、失败恢复；随行为更新       |
| `spec/`          | 当前跨模块接口、数据格式、顺序、所有权和限制；与实现同变更更新 |
| `dev/`           | 开发、测试、评测和诊断操作；不手工复制源码目录与命令全集       |
| `research/`      | 可核验的调研和实验；明确测量条件、版本、日期与样本             |
| `.agents/notes/` | 代码与当前文档不能充分说明的长期理由、备选、后果和验证缺口     |

模块自身的用法可放模块 README。已完成工单中的当前契约、理由和实验分别归位，剩余过程内容可删除。删除以独有信息是否已保存为依据，不以文件年龄或清理配额为依据。

## 写作与引用

段落写在一行内；标题使用 Markdown 标题语法，表格只表达并列事实。保留理解接口所需的条件、失败、顺序与兼容保证。示例优先使用最短可运行路径；精简不能删除必要前提。

当前页面采用稳定主题名；独立实验报告使用 `YYYY-MM-DD-中文主题.md`。来源内容跨测量时点时逐项说明，不用文件更新时间冒充实验日期。

外部资料使用脚注，文末设“### 参考文献”。内部链接指向事实归属；代码注释引用模块和符号，不依赖易漂移的行号。页面改名或删除时同步修复 Markdown 链接、裸路径和代码注释。

`docs/README.md` 是统一导航，小目录不另建重复索引。研究正文按主题组织，数据、图源与生成脚本集中在 `research/evidence/<主题>/`，由所属报告和包内说明交代用途与复核边界。没有消费者且不承载独有证据的草稿和重复生成物可删除；不能仅为减少正文数量丢失实验依据。Notes 的 `archived/` 采用哈希与可信历史保护；普通报告允许有依据地勘误和合并，不伪装为哈希封存件。

## 发布与验证

公开文档不包含凭据、内部主机与部署细节。用户配置路径使用产品环境变量或语义名称；实验现场只作来源说明，不把本机未入库路径当作可复现依赖。

提交前运行维护检查、Markdown lint 和实际受影响的示例。链接检查验证本地文件存在性和导航可达性，不验证节锚或事实；产品命令、API 和生成物须分别验证。声明实际覆盖与未验证条件，不以检查器全绿替代内容审阅。
