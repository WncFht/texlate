## 1. P3 磁盘保留策略落地（`702e1554`）

trizone 四区（`$TEXLATE_BENCH_ROOT` 下 ledger/runs/vault/lake）的保留面按 `spec/bench-trizone.md` §3.10 收口[^trizone]，三条腿[^retention]：

- **vault slim（splice 即焚）**：`kernel/vault.py::slim_splice`——splice 叶只留主干同名成品 pdf + `.xlat-arm.json` + 同名 log（无主干匹配时退化为最大 pdf），tex 源/重复 pdf/根图/`figs/`/`anc/` 全删；meta `files` 重写、manifest 落 `op=slim` 行、幂等。存量回填实测释放 2.28G。
- **vault cas-link**：`kernel/vault.py::cas_link_tree`/`cas_link_leaves` + `CAS_LINK_FLOOR=256KiB`——≥256KiB 的叶文件内容寻址入 `lake/objects/{kind}/` 后原位硬链回，多叶同内容共用一个 inode。存量回填链接 1,363 文件 / 2,303 MiB 叶字节（净省约 1.05G）。`lake/objects` 现 1.4G，vault 叶侧 4,916/8,988 文件为多链接。

- 验证：`bench vault verify` 全量复核 8,491 文件 0 坏（校验时点口径）。

## 2. dedup 预言机 meta 腿按 kind 裁剪（`e9c18aa6`）

`kernel/dedup.py` 的五态裁决（UNSEALED/CLAIMED/VERIFIED/MISSING/ABSENT）中，VERIFIED 的 vault-meta 腿此前只回标量"该 cell key 存在完好 meta"——但一份 meta 只担保它 `files` 字典里声明的 kind。retry39 暴露的实害：35/39 篇有 `{state}`-only harvest（xlat 崩溃前的检查点），无 `vault/zh`；标量 meta_ok 让 xlat（`need={zh,state}`）误判 VERIFIED 永久 dedup，compile needs 找不到 DONE 行连 skip，fixloop 报 `upstream:no DONE compile row`——永久死锁[^dedupfix]。

修复：`_scan_vault_meta` 改回四元组 `(bytes_ok, missing, io_error, kinds)`，kinds = 所有字节完好行的 `meta["files"]` 键并集；`_verified` meta 腿要求 `need <= meta_kinds`（paid_pool 腿不变——付费终态行本就担保全部 mutates）。回归钉案 `tests/kernel/test_dedup.py`：`test_partial_kind_meta_does_not_verify_uncovered_needs`（state-only 不铸 xlat VERIFIED）与 `test_split_kinds_across_copies_verify`（zh/state 分存两副本仍 VERIFIED）双向钉死。**下游含义**：修复后那 35 篇下一跑将判 ABSENT → xlat 重跑并自动续用 vault/state 检查点，不再空转。

## 6. dedup×harvest 三洞修复与 vault rekey（2609.20519 实证）

2609.20519 在 v1 键域报「no intact committed copy」追查出一组系统性洞——表象像 tombstone，实为 **dedup 终态与 harvest 触发点的结构错配**，三洞并发：

1. **免费段 verdict-dedup 不验字节**：step-2 `_last_outcome` 只看账本 DONE 行——行在只证「跑过」，不证产物在押。e2e_real-6 的 fixloop/layoutqc `declined:*` 行在 declined 透明化（`199f0c98`）**之前**被铸成 DONE 判定基，之后变透明——但 e2e_real-8 起跑时旧行仍按 DONE 读，fixloop/layoutqc 撞 dedup 终态。
2. **`_release_verified` 腿无字节担保**：付费 oracle 认「claim release/fate=verified」即 VERIFIED——花的钱核销过≠字节在押（sweep/清理可事后核销字节）。
3. **dedup 终态跳过 harvest**：`_harvest_last_mutating` 只在 `STATUS_DONE` 终态触发——dedup 行不触发。e2e_real-8 的 xlat/compile 真跑产出 zh/splice 字节躺在工作树，layoutqc dedup 后 `remove_cell_tree` 整树清零——字节从此物理蒸发，v1 键域永久饥饿。同机理批量实证：e2e_real-2/-3 共 99 格 `declined:qc_no_input`。

**修复三件套**[^threeholes]：

- **fix A**：`_harvest_last_mutating` 闸放宽为 `status not in STATUS_DONE | {"dedup"}`——dedup 快终态在 last_mutating 也收 harvest：本段 dedup 只证本段活干完，上游本跑真产出的字节仍在树上待押，dedup 行是 `remove_cell_tree` 前最后一个 custody 点。
- **fix B**：mutates 格的 verdict-dedup 加字节闸——命中 DONE/dedup 判定时对 `stage.mutates` 调 `oracle.check`：ABSENT/MISSING（无在押副本含登记丢失）放行重跑自愈，VERIFIED/CLAIMED/UNSEALED 维持 dedup。免费重算零成本，regen 闸护的是花费不是重算。
- **fix C**：`vault.rekey(src_variant, dst_variant)` + `bench vault rekey --from - --to v1`——把完好副本的字节换键重押（harvest 走全锁径，op=rekey 留谱系），默认只搬 `REKEY_KINDS={zh,state}`（付费产物）；splice/layoutqc 刻意不搬——免费可重生成，搬了反而喂字节闸铸 VERIFIED 锁死 regen。

**顺带挖出的存量 bug**：`events.ASSET_KINDS` 缺 `layoutqc`（vault.KINDS 早有第四种）——layoutqc 时代所有 harvest commit 的 T_ASSET emit 在第一种就抛 EventError 死循环，assets 投影整批丢行。已补。

**rekey 实跑**（`bench vault rekey --from - --to v1 --arm real`）：139 格 zh 从 `-` 键域搬入 v1，0 错误；2609.20519 `vault restore --variant v1` 实证可还原（16 文件含 main.tex）。普查残账：260 个 v1-epoch real 格中 47 格全变体无完好 zh——39 格是烧过钱字节丢了的真空洞（21 格 v1 时代真跑被害于洞 3、13 格 zhstore records-import 只铸 verdict 从未有字节、5 格 dirty 稿），8 格从未产出（skip/reject/error 正当缺席）。39 格要归零只能付费重译，待放行。

## 7. fixloop 版面规则族 + 缺包核销

探针批暴露的版面缺陷原无修复出口（qc_wanted 补票格 compile clean 无 '!' 错可分诊），补全链路：

- **redlines.py** 新增两条 rules-only 红线 `overfull_hbox`/`float_too_large`——版面质量信号不进 engine 判红面（挂 rules 切片不挂 engine/judge）。
- **10-taxonomy.yaml** 新增 warnings 段伪类别 `warn_overfull`/`warn_float_big`（序位在缺字族后——缺字语义损伤更重先分诊）。
- **97-layout.yaml**（新分片）两条规则：`para_loosen_overfull`（warn_overfull → `para_loosen`：`\emergencystretch=1.5em + \tolerance=2000` preamble 尾注——TeX 三遍排版真修复，不设 `\hfuzz` 遮掩证据面）、`float_big_h_demote`（warn_float_big → `float_h_demote`：[H] 超高非浮体降级翻回真浮体）。
- **缺包核销**：aastex631.cls/undertilde.sty/xetex-inputenc.sty 三缺包标记复查——90-shim-legacy.yaml 早有 shim（aastex631 真件标记 stub、undertilde `\utilde`→`\widetilde` 降级、xetex-inputenc noop stub 因 xelatex 原生 UTF-8 免载），探针批的 missing_file 失败格是 shim 投递链未触达的历史格，非规则缺口。
- **`_vendored_source` casefold 补扫**：vendor 仓收 CTAN 原名件（`IEEEconf.cls` 大写骆驼），payload 按稿面小写请求——精确 miss 后按 casefold 补扫，落盘仍写 payload 原名（2310.16788 实证）。

钉案 `tests/test_fixloop_layout.py` + `tests/test_fixloop_vendorcwd.py` 扩展。
